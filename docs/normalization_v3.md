## 1. 무엇이 문제였나

2차는 20개 중 **5개 화면만** 카드 밀도를 낮췄다. 나머지 15개는 측정 대상에도 없었고,
그 결과 화면마다 정돈 수준이 달라 서비스 전체로 보면 여전히 난잡했다.

측정으로 확인한 실제 상태:

| 지표 | 3차 이전 |
| --- | --- |
| 본문 폭 | **3종** — 960이 아니라 1120 / 1192 / 1440이 섞여 있었다 |
| 카드 총계 | **64장** (`human-review` 7 · `team-members` 7 · `charter` 6 · `documents` 5 · `ai-review` 5 …) |
| 채운 버튼 2개 이상 | 3화면 (dashboard 2 · team-members 2 · ai-structure 4) |
| 상태색 면 배경 누수 | 2건 (`human-review`의 warning 틴트 박스, `team-reset`의 error 틴트 박스) |

이번 작업은 **Playwright로 매 단계 계측하며** 진행했다 — 감이 아니라 숫자로 확인한다.

## 2. 적용한 규칙

지시서 2장을 그대로 따랐다. 핵심은 하나 —
**테두리와 색을 정보의 "양"이 아니라 "종류"에만 쓴다.**

### 2.1 박스 기준

> 이 정보 단위가 **독립적으로 선택·승인·삭제·이동**될 수 있는가?

"예"일 때만 `Card`. 아니면 `Section`(여백+타이포) 또는 `Disclosure`(접기).

| Card로 남긴 것 | Card에서 내린 것 |
| --- | --- |
| 개별 리뷰 코멘트 · 개별 규칙 · 개별 검토 항목 | 같은 문서의 속성들 (문서 요약, 최근 변경) |
| 입력 폼 (대체 승인권자 지정, 초기화 확인) | 설명·안내 (지정 조건, 주의사항, 연동 안내) |
| 원문/번역 대조 패널 (독립 대조 단위) | 통계 숫자 묶음 |

### 2.2 색

- 브랜드색 배경은 **화면당 주 액션 버튼 1개**에만.
- 상태색은 `StatusBadge` / `RaciChip` / `AiDisclaimer` **안에서만**.
  면 배경으로 쓰던 곳은 전부 제거하고 텍스트 색 · 좌측 3px 띠로 대체했다.
- 회색조는 `line`(경계) + `neutral-50`(배경) 두 단계로.

### 2.3~2.6

타이포 위계로 중요도 표현 · 본문 폭 단일화 · 섹션 간 여백 32px · 아이콘과 버튼 절제.

## 5. 판단이 필요했던 지점

1. **본문 폭을 960px으로 정했다.** 지시서가 예시로 든 값이고, 실제로 넣어 보니
   표(문서 목록 6열, Doc PR 4열)와 2단 레이아웃이 다 들어간다. 1120보다 확실히
   조용하게 읽힌다.

2. **`charter`를 목표(6 유지)보다 낮은 4로 줄였다.** 지시서 3.1은 "6 유지하되 내부
   정리"였지만, 2.1의 박스 기준을 적용하면 현재 상태·연동 안내는 독립 단위가 아니다.
   규칙 3장은 지시대로 Card를 유지했다.

3. **번역문 패널의 info 틴트 배경을 뺐다.** 1차 원칙 5(번역본은 원문과 시각적으로
   구분)와 3차 2.2(상태색은 배지 안에서만)가 충돌하는 지점이다. 상단 3px 띠 +
   "AI 번역" 라벨로 구분이 유지되므로 면 배경만 제거했다.

4. **인증 화면 2개는 폭 통일 대상에서 분리했다.** 셸이 없는 전체 화면 중앙 정렬
   레이아웃이라 "본문 콘텐츠 영역"과 성격이 다르다. 대신 두 화면의 카드 폭을
   400px으로 맞췄다.

## 6. 남은 것

- 1·2차에서 이월: 번역 화면 블록 단위 대조, 에디터 인라인 서식,
  `CURRENT_USER` mock 고정, 승인권자 지정 ↔ 팀원 관리 미통합.

  더 줄이면 오히려 정보 구분이 흐려진다 — 현 상태가 하한으로 본다.
