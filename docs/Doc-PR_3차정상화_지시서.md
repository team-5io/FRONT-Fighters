# Doc PR — 3차 정상화 지시서 (시각 정리)

> `normalization_v2.md` 이후 작업. 기능·데이터·컴포넌트 구조는 전부 유지한다.
> **이번 라운드는 새 기능을 만들지 않는다. 이미 만든 화면을 노션 수준으로 깔끔하게
> 다듬는 것만 한다.**

---

## 0. 왜 다시 하나

2차는 20개 화면 중 **5개(대시보드·Doc PR 상세·RACI 역할 관리·팀 설정·CIO 1차 검토)만**
카드 밀도를 낮췄다. 2차 결과서 7~8장이 스스로 밝혔듯 `human-review`(카드 7) ·
`team-members`(카드 7) · `charter`(카드 6)는 손대지 않았고, 그 밖에 문서 목록 /
Doc PR 목록 / 문서 상세 / 번역 보기 / 승인권자 지정 / 팀 용어집 / RACI 이외 설정
화면들은 **애초에 카드 밀도 측정 대상에 포함되지도 않았다**. 그 결과 5개 화면과
나머지 15개 화면의 시각적 정돈 수준이 서로 달라, 서비스 전체로 보면 여전히 난잡하게
느껴진다.

이번 라운드의 목표는 하나다: **2차가 5개 화면에 적용한 기준을 예외 없이 20개
화면 전부에 동일하게 적용한다.** 새 정보 구조를 설계하는 게 아니라, 이미 있는 정보를
"박스 쌓기"가 아닌 방식으로 다시 배치하는 시각 작업이다.

**브랜드 테마는 그대로 둔다.** `main-500 #9000FF` 등 색 토큰, `DESIGN.md`의 컴포넌트
정의, 1·2차가 만든 `StatusBadge`/`RaciChip`/`CioBadge`/`Disclosure`/`Card`/`Section`은
전부 유지·재사용한다. 이번 작업은 색을 바꾸는 게 아니라 **그 색을 얼마나 자주,
얼마나 세게 쓰는지를 줄이는** 작업이다.

---

## 1. 지금 난잡해 보이는 이유 (진단)

노션이 깔끔하게 느껴지는 이유는 요소가 적어서가 아니라, **테두리와 색이 정보의
"양"이 아니라 "종류"를 표시하는 데만 쓰이기 때문**이다. 우리 화면은 반대로 되어 있을
가능성이 높다:

- 같은 화면 안에서 **테두리 있는 박스가 너무 많다** — 원래 독립적이지 않은 정보(같은
  섹션에 속한 항목들)까지 각자 카드로 감싸 놓으면, 화면 전체가 "박스의 벽"처럼 읽힌다.
- **색이 장식으로 쓰인다** — 상태를 나타내지 않는 곳에도 브랜드색/의미색 배경이
  깔려 있으면, 정작 중요한 상태 배지가 묻힌다.
- **위계가 크기가 아니라 박스 개수로 표현된다** — 중요한 정보와 부차적 정보가 똑같은
  카드 크기·테두리 굵기를 갖고 있어 눈이 어디부터 봐야 할지 모른다.
- **폭이 화면마다 다르다** — 2차까지도 카드 폭이 348/1033, 352/959, 352/993처럼
  화면마다 미세하게 다른 값이 남아 있었다(1차 결과서 4장). 이런 미세한 불일치가
  쌓이면 전체가 "각 화면이 따로 논다"는 인상을 준다.

## 2. 시각 정리 규칙 (전 화면 공통, 예외 없음)

### 2.1 박스(Card) 사용 기준
아래 질문에 **"예"일 때만** `Card`(테두리+배경)를 쓴다. 아니면 `Section`(여백+타이포
위계, 테두리 없음) 또는 `Disclosure`(접기)로 대체한다.

> 이 정보 단위가 **독립적으로 선택·승인·삭제·이동**될 수 있는가?
> (예: 개별 Doc PR, 개별 리뷰 코멘트, 개별 팀원, 개별 용어집 항목 → Card 적합)
> (아니오: 같은 문서의 속성들, 같은 사유의 하위 항목들, 통계 숫자 여러 개 →
> Section 안에서 구분선/여백으로만 구분)

이 기준으로 아래를 재검토한다 — 특히 아직 손대지 않은 화면:
- **사람 리뷰(`#/human-review`, 카드 7)** — 리뷰 코멘트는 Card 유지(독립 단위가 맞음).
  나머지(작성자 정보, 처리 이력, 문서 메타)는 Section으로 합친다.
- **팀원 관리(`#/team-members`, 카드 7)** — 팀원 개별 행은 `DataTable`의 행으로(이미
  1차가 만든 컴포넌트), 대체 승인권자 지정 폼 하나만 독립 Card로 남긴다.
- **협업 규칙(`#/charter`, 카드 6)** — 규칙 3장은 각각 독립적으로 수정·채택되는 단위이니
  Card 유지가 맞다. 대신 카드 **내부**의 라벨/설명/셀렉트를 다시 여백으로 정리하고,
  카드 자체의 테두리 두께·그림자를 낮춘다.

### 2.2 색 사용 기준
- 화면 하나에서 **브랜드색(main)은 주 액션 1개(버튼 또는 활성 탭)에만** 배경으로
  쓴다. 나머지는 텍스트/아이콘 컬러 정도로만 절제해서 쓴다.
- 상태색(success/warning/error/info)은 **오직 `StatusBadge`/`RaciChip`/`AiDisclaimer`
  안에서만** 쓴다. 카드 배경이나 섹션 배경을 상태색 틴트로 채우지 않는다(현재 남아있는
  화면이 있다면 제거).
- 회색조는 두 단계로 제한한다 — 경계선용 `line`(`rgba(0,0,0,0.1)`), 배경용
  `neutral-50`. `neutral-75`/`neutral-100`은 표 헤더띠·구분선 등 정말 필요한 곳에만.

### 2.3 타이포 위계로 정보량을 표현
- 카드 개수를 늘리는 대신 **제목 크기(H1/H2/H3)와 텍스트 색 농도(ink/muted)**로
  중요도를 표현한다. "이 화면에서 가장 중요한 한 가지"는 화면 상단에 다른 모든
  텍스트보다 확실히 크게 둔다(2차가 대시보드·Doc PR 상세에 적용한 "주인공 하나" 원칙을
  타이포로 구현한 것 — 이걸 20개 화면 전부의 기본값으로 삼는다).
- 부차 정보(메타데이터, 타임스탬프, 카운트)는 본문보다 작고 옅은 색으로, 항상 같은
  스타일(속성 줄 패턴)로 통일한다.

### 2.4 본문 폭 통일
- **모든 화면의 본문 콘텐츠 영역 최대 폭을 하나의 값으로 고정**한다(예: 960px, 이미
  1차가 도입한 `Page` 컴포넌트가 폭을 소유하고 있으니 그 값을 전 화면에 강제 적용).
  화면마다 348/352, 1033/993/959로 흔들리던 값을 전부 이 컴포넌트 기본값 하나로
  수렴시킨다. 예외를 두지 않는다 — Document Graph 캔버스처럼 전체 폭이 필요한
  화면은 명시적으로 "풀블리드가 필요한 화면"으로 분류하고 그 외엔 전부 통일 폭을 쓴다.

### 2.5 여백 리듬 재확인
- 2차 결과서가 확인한 대로 `4/8/12/16/24px` 리듬은 유지한다. 다만 **박스 개수가
  줄어드는 만큼 섹션 사이 세로 여백을 늘려서(예: 32px)** "빈 공간이 곧 구분"이라는
  노션의 감각을 살린다. 테두리를 없앤 자리를 다른 테두리로 채우지 않는다.

### 2.6 아이콘·버튼 절제
- 화면당 동시에 강조된(색이 채워진) 버튼은 하나만 둔다. 나머지 액션은 outline/ghost.
- 장식용 아이콘(정보 전달에 기여하지 않는 아이콘)은 제거한다. 아이콘은 상태·유형을
  나타낼 때만 쓴다.

## 3. 화면별 작업 지시

### 3.1 우선순위 1 — 2차가 남긴 3개 화면
| 화면 | 현재 카드 수 | 목표 |
| --- | --- | --- |
| `#/human-review` | 7 | 3 이하 (리뷰 코멘트 목록만 Card, 나머지 Section) |
| `#/team-members` | 7 | 2~3 (팀원 목록은 DataTable, 대체 승인권자 폼만 Card) |
| `#/charter` | 6 | 6 유지하되 카드 내부·테두리·그림자 정리 |

### 3.2 우선순위 2 — 2차 카드 밀도 측정에서 아예 빠졌던 화면 전부
2차가 손대지 않은 나머지 12개 화면(로그인 계열 3개 제외 — 이미 단순함)에
2.1~2.6 규칙을 동일 적용하고, 2차와 같은 방식으로 "이전 카드 수 → 이후 카드 수" 표를
작업 기록에 남긴다.
- 문서 목록 / Doc PR 목록 — 표(`DataTable`) 위주라 카드 밀도는 낮을 가능성이 높지만,
  검색·필터 바와 상단 요약이 별도 카드로 떠 있다면 Section으로 합친다.
- 문서 작성/편집(`#/write`) — 블록 에디터 자체는 카드가 아니어야 한다(캔버스). AI
  패널 펼침 상태의 카드 밀도도 이번 기준으로 재검토한다.
- 번역 보기 — 원문/번역 패널 2개는 Card 유지가 합리적(독립 대조 단위)이나 그 주변
  부가 정보(원문 보존 안내 등)는 Section으로.
- Document Graph — 캔버스는 풀블리드 예외. 다만 좌측/우측에 뜨는 안내 패널이 있다면
  2.1~2.6 규칙 적용.
- 승인권자 지정 / RACI 역할 관리(2차에서 매트릭스 중심으로 이미 정리했지만 재확인) /
  팀 용어집 관리 / 팀 설정(2차에서 카드 0으로 정리했지만 재확인).

### 3.3 전역 셸(사이드바 · 상단바)
- 사이드바: 항목 사이 구분을 배경색 박스가 아니라 좁은 여백 + 선택 시에만 옅은
  강조(현재 텍스트 라벨 기준 -23px 칩 위치 등 1차가 남긴 미세 조정값은 유지)로.
  강조색은 브랜드 1색만 쓴다.
- 상단바: 이미 2차 이전에 80→52px로 축소됐다 — 이번엔 그 안의 대비(그림자, 테두리
  두께)까지 낮춘다.

## 4. 작업 순서 제안

1. **`Page` 본문 폭을 하나의 값으로 강제**(2.4) — 이게 다른 모든 화면의 기준선이 된다.
2. **`#/human-review`, `#/team-members`, `#/charter`** — 2차가 미룬 3개를 먼저 정리한다.
3. **나머지 12개 화면 순회** — 2.1(박스 기준)부터 적용하고, 색·타이포·여백 규칙을
   따라 정리한다.
4. **전역 셸 정리** — 사이드바/상단바.
5. 전체 20개 화면을 한 번 더 스윕하며 **화면 간 폭·여백·색 사용이 실제로 통일됐는지**
   눈으로 대조한다(1차·2차가 여러 번 지적한 "화면마다 미세하게 다른 값" 재발 방지).

## 5. 완료 기준 (Definition of Done)

- [ ] 20개 화면의 본문 최대 폭이 하나의 값으로 통일됐다(Document Graph 등 명시적
      풀블리드 예외 제외).
- [ ] `human-review` / `team-members` / `charter`의 카드 밀도가 표(3.1)의 목표치까지
      낮아졌다.
- [ ] 2차에서 다루지 않았던 12개 화면 전부에 대해 "이전 카드 수 → 이후 카드 수"가
      작업 기록에 남아 있다.
- [ ] 어떤 화면에서도 상태색(success/warning/error/info)이 `StatusBadge`/`RaciChip`/
      `AiDisclaimer` 바깥에서 배경색으로 쓰이지 않는다.
- [ ] 화면당 배경이 채워진(강조) 버튼이 동시에 하나뿐이다.
- [ ] 브랜드 컬러(`main-500` 등 `DESIGN.md` 토큰)는 값 자체가 전혀 바뀌지 않았다 —
      바뀐 것은 사용 빈도와 위치뿐이다.
- [ ] 1·2차가 만든 컴포넌트(`Card`/`Section`/`Disclosure`/`DataTable`/`StatusBadge`/
      `RaciChip`/`CioBadge`/`Page`)가 삭제되지 않고 이번 정리에 그대로 쓰였다.
- [ ] API 호출 코드가 추가되지 않았다(기존과 동일하게 mock 유지).
- [ ] 20개 라우트 전수 스윕 시 콘솔 에러 0건, 가로 오버플로 0건.
