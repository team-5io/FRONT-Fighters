# Doc PR — 5차 정상화 지시서 (레이아웃 구역·정보 밀도)

> `normalization_v4.md` 이후, 실제 캡처 화면(대시보드·문서 목록·Doc PR 목록·Document
> Graph·문서 작성) 5장을 직접 검토하고 작성한 지시서. 이번엔 컨테이너(테두리/배경)를
> 더 줄이는 게 아니라 **레이아웃 구조 자체**를 다시 본다.

---

## 0. 재진단 — 상자를 없앴는데 왜 아직 난잡한가

4차까지 세 차례에 걸쳐 카드·배지·입력창의 테두리와 배경을 계속 줄여왔고, 실제로
효과가 있었다(64→44장, 컨테이너 477→323개). 그런데도 캡처를 보면 여전히 바쁘다.
이유는 **컨테이너 개수와 난잡함이 같은 것이 아니기 때문**이다. 난잡함을 만드는 다른
축이 세 가지 더 있는데, 지금까지 어느 라운드도 이걸 재지 않았다.

1. **동시에 열려 있는 레이아웃 구역의 수.** 문서 목록·Document Graph·문서 작성
   화면은 전부 `사이드바 + 본문 + 우측 패널`(작성 화면은 여기에 하단 플로팅까지)
   구조다. 각 구역 안의 요소가 아무리 절제돼 있어도, **구역이 3~4개 동시에 켜져
   있으면 눈이 어디를 봐야 할지 매 순간 다시 판단해야 한다.**
2. **구역 하나의 정보 밀도.** 우측 패널들이 대표적이다 — 문서 목록의 미리보기
   패널은 제목+상태배지, 설명, RACI 칩, "최근 변경" 목록(3항목), "연결된 Doc PR"
   목록(2항목)까지 **5개의 서로 다른 정보 그룹**을 한 화면에서 동시에 펼쳐 보여준다.
   테두리가 없다 보니 이게 하나의 덩어리로 안 보이고, 텍스트 줄이 계속 이어지는
   것처럼 읽힌다. Document Graph 우측 패널도 마찬가지로 노드 정보 + 액션 2개 +
   영향받는 문서 목록(4항목, 각각 배지 2개 포함) + 관계 사용처 목록(2항목) +
   담당 칩까지 쌓여 있다.
3. **화면마다 반복되는데 그 화면의 주인공은 아닌 요소.** "이 팀에서 내 역할 —
   할 수 있는 것" 권한 안내 줄이 문서 목록·Doc PR 목록·문서 작성 화면 상단에
   똑같이 반복 등장한다. 정보 자체는 유용하지만(RACI 가시성 원칙, 1차 지시서),
   **매 화면 최상단 근처에 항상 켜져 있을 만큼 그 화면의 핵심은 아니다.**

**결론**: 이번 라운드는 상자를 지우는 대신, **"화면당 몇 개의 구역이 동시에 켜져
있는가"와 "구역 하나가 몇 개의 정보 그룹을 동시에 보여주는가"를 줄인다.**

## 1. 새 원칙

### 원칙 A — 화면당 레이아웃 구역은 최대 2개
`사이드바`는 항상 켜져 있는 셸이라 이 카운트에서 제외한다. 그 외 `본문`과 `보조
패널(우측)` 두 구역까지만 동시에 허용한다. 지금처럼 본문 + 우측 패널 + 하단
플로팅이 동시에 뜨는 화면(작성 화면)은 플로팅을 "필요할 때만 나타나는 것"으로
명확히 하고(이미 접힘 상태 기본값이므로 그대로 유지), 상시 구역 카운트에는
포함하지 않는다.

### 원칙 B — 보조 패널도 "주인공 하나" 규칙을 그대로 적용받는다
지금까지 "화면당 주인공 하나"는 화면 전체에만 적용해왔다. 이번엔 **보조 패널
내부에도 같은 규칙을 적용**한다. 보조 패널은 기본적으로 딱 하나의 정보 그룹(가장
중요한 것 — 보통은 "요약")만 펼쳐서 보여주고, 나머지는 `Disclosure`로 접어 둔다.

- 문서 목록 우측 패널: 기본 노출 = 제목/상태/설명/RACI. **"최근 변경"과 "연결된
  Doc PR"은 접어서** 필요할 때만 펼친다.
- Document Graph 우측 패널: 기본 노출 = 제목/상태/문서 열기·관계 편집 액션.
  **"변경 시 영향받는 문서"와 "이 관계를 쓰는 곳"은 탭 두 개로 분리**하거나
  둘 다 접어서 하나씩만 펼치게 한다.
- 문서 작성 우측 패널: 기본 노출 = 권한 한 줄(아래 원칙 C 적용 후 축소된 형태).
  "연결된 문서" 목록은 접어 둔다 — 작성 중엔 본문이 주인공이어야 한다.

### 원칙 C — 반복되는 권한 안내는 상시 배너에서 내린다
"이 팀에서 내 역할 — 할 수 있는 것" 배너를 문서 목록·Doc PR 목록·문서 작성에서
**제거**하고, 대신:
- 브레드크럼 옆이나 헤더 우측에 **RACI 칩 하나만** 인라인으로 남긴다(예: 제목 옆에
  작게 "A 승인 책임").
- 칩을 클릭하거나 hover하면 "할 수 있는 것" 설명과 "팀 관리자" 여부가 팝오버로
  뜬다.
- 이 정보가 화면의 주인공이어야 하는 곳(RACI 역할 관리, 4차가 만든 마이페이지)은
  지금처럼 본문에 그대로 남긴다 — 원칙 C는 "반복되는 부차 정보"에만 적용된다.

### 원칙 D — 상단 통계·메타 줄의 색상 사용 제한
대시보드 상단 통계 줄("내 역할 A 승인 책임 · 전체 Doc PR 24 · 검토 대기 7 ·
승인 완료·Merge 대기 5 · CIO 반려 권고 +3")처럼 여러 숫자가 한 줄에 나열되는
곳은 **강조가 정말 필요한 숫자 하나(예: 지금 내가 처리해야 할 것)만 브랜드색이나
상태색을 쓰고, 나머지는 전부 동일한 회색조 텍스트**로 통일한다. 지금처럼 보라
배지 + 검정 텍스트 + 주황 텍스트 + 파랑 "+3"이 한 줄에 섞이지 않게 한다.

### 원칙 E — 액션 밀집 구역은 주/부로 나눈다
문서 작성 화면 툴바(관련 문서 연결 · 번역 보기 · 작성 도우미 · 초안 저장 ·
Doc PR 생성)처럼 클릭 가능한 요소가 한 줄에 5개 이상 몰리는 곳은:
- **주 액션 1개**(Doc PR 생성)만 채운 버튼으로 남긴다.
- **부속 액션**(관련 문서 연결·번역 보기·작성 도우미)은 `⋯ 더보기` 메뉴로 묶거나,
  최소한 시각적으로 더 작게·연하게 만들어 주 액션과 구분한다.
- 초안 저장처럼 자동으로 일어나도 되는 동작은 "최근 저장 방금 전" 같은 상태
  텍스트로 대체하고 버튼 자체를 없애는 것도 검토한다.

### 원칙 F — 아이콘·배지 어휘를 하나의 표로 고정
지금 화면마다 상태 점, RACI 색 원, 언어 태그(EN/JA), AI 마커(✦), 잠금 아이콘,
사이드바 아이콘(집/문서/별/그래프/연필)이 전부 다른 규칙으로 등장한다. 각각의
의미는 필요하지만, **이 조합 자체를 `docs/icon-system.md` 한 곳에 표로 고정**해
새 화면을 만들 때마다 새 마커를 즉흥적으로 추가하지 않게 한다. 이번 라운드에서
빠진 게 있다면 채우기만 하고, 새 종류를 만들지는 않는다.

## 2. 화면별 작업 지시 (캡처 기준)

### 대시보드
- 통계 줄 색상 절제(원칙 D). 카드 3개·Disclosure 리스트 5개 구조는 이미 적절하니
  유지한다.

### 문서 목록
- 권한 안내 배너 제거 → 인라인 RACI 칩(원칙 C).
- 우측 미리보기 패널: 요약만 기본 노출, "최근 변경"·"연결된 Doc PR" 접기(원칙 B).
- 언어 태그(EN/JA)는 표 안에서 유지하되 우측 패널에서는 제목 옆 대신 속성 줄로
  옮겨 시각적 밀도를 낮춘다.

### Doc PR 목록
- 권한 안내 배너 제거 → 인라인 RACI 칩. 이 화면은 이미 단일 구역(본문만)이라
  구조 자체는 유지한다.

### Document Graph
- 우측 패널의 "영향받는 문서"/"이 관계를 쓰는 곳"을 탭으로 분리하거나 기본
  접힘(원칙 B). 범례·조작 안내는 캔버스 안에 이미 잘 정리돼 있으니 유지한다.

### 문서 작성
- 툴바를 주 액션(Doc PR 생성) + 더보기 메뉴로 재구성(원칙 E).
- 우측 패널: 권한 정보는 인라인 칩으로 축소(원칙 C), "연결된 문서" 목록은 기본
  접힘(원칙 B).
- 하단 "작성 도우미" 플로팅 버블은 지금 형태(접힘 기본, 배지로 제안 개수 표시)가
  2차 지시서 의도와 정확히 일치한다 — **그대로 유지**.
- 블록 에디터 본문 자체(토글, 체크박스, 코드 블록, 하단 마크다운 팁 줄)는 이미
  절제돼 있다 — 손대지 않는다.

## 3. 작업 순서 제안

1. **원칙 C(권한 배너 제거 → 인라인 칩)** — 세 화면에 반복되던 배너 하나를
   없애는 것만으로 체감 밀도가 가장 크게 줄어든다. 가장 먼저 처리한다.
2. **원칙 B(보조 패널 내부 접힘)** — 문서 목록·Document Graph·문서 작성 우측
   패널에 `Disclosure`/`Tabs` 적용.
3. **원칙 E(작성 화면 툴바 정리)**.
4. **원칙 D(대시보드 통계 줄 색상 정리)**.
5. **원칙 F(아이콘 표 정리)** — 문서화 작업이라 마지막에 한 번에 처리.

## 4. 완료 기준 (Definition of Done)

- [ ] 사이드바를 제외하고, 어떤 화면에서도 동시에 켜진 레이아웃 구역이 2개(본문 +
      보조 패널 1개)를 넘지 않는다.
- [ ] 보조 패널이 있는 모든 화면(문서 목록·Document Graph·문서 작성)에서 패널의
      기본 노출 정보 그룹이 1개이고, 나머지는 접혀 있다.
- [ ] "이 팀에서 내 역할 — 할 수 있는 것" 전체 폭 배너가 문서 목록·Doc PR 목록·
      문서 작성 화면에서 사라지고 인라인 RACI 칩 + 팝오버로 대체됐다.
- [ ] 대시보드 통계 줄에서 강조색이 쓰인 항목이 1개뿐이고 나머지는 동일한
      회색조다.
- [ ] 문서 작성 화면 툴바에서 채운 버튼이 1개(Doc PR 생성)뿐이고 나머지 액션은
      더보기 메뉴 또는 축소된 스타일이다.
- [ ] `docs/icon-system.md`가 존재하고 현재 쓰이는 모든 마커(상태 점·RACI 원·
      언어 태그·AI 마커·잠금 아이콘·사이드바 아이콘)를 표로 정리했다.
- [ ] 위 변경 전후로 같은 화면 5장(대시보드·문서 목록·Doc PR 목록·Document Graph·
      문서 작성)을 다시 캡처해 비교 기록을 남긴다 — 이번 라운드는 진단 자체가
      스크린샷에서 나왔으므로, 검증도 스크린샷 대조로 마무리한다(컨테이너 개수
      계측만으로 끝내지 않는다).
- [ ] 1~4차가 만든 컴포넌트·데이터(`Disclosure`, `RaciChip`, `StatusBadge`,
      `Page`, `status.js`, `raci.js`, `nav.js`)가 삭제되지 않고 재사용됐다.
- [ ] 브랜드 컬러 값 불변, API 호출 코드 없음, 21라우트 스윕 콘솔 에러 0건 —
      이전 라운드와 동일하게 유지.
