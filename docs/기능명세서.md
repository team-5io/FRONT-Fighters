## 1. 프로젝트 개요
---
### 한 줄 정의
Doc PR — 문서를 코드처럼 관리하는 팀 협업 문서관리 시스템

### 제품 목표
언어·문화·지리·조직의 경계를 넘어 협업하는 팀이 문서 작성부터 리뷰·승인까지 코드 PR과 같은 방식으로 관리하며 프로젝트의 생각과 결정을 안전하게 보호하도록 한다. 팀의 문서·문서 간 관계·팀원의 관여 이력을 통합적으로 파악하는 AI(CIO)가 7개 기능을 조율해 지리·언어·문화·조직 네 가지 협업 경계를 실질적으로 넘도록 돕는다.

### 배경
AI가 코드를 작성하는 시대가 되면서 개발자의 핵심 역할은 코딩 자체보다 문제 정의, 서비스 설계, 기획 문서 작성, AI 결과 검토로 이동하고 있다. 이에 따라 프로젝트에서 가장 중요한 자산은 코드가 아니라 문서와 의사결정 과정이 되었고, Code PR이 코드를 보호했듯 이제는 Document PR이 문서를 보호해야 한다는 판단에서 이 서비스를 기획했다. 이 프로젝트는 지리·언어·문화·조직 네 가지 경계를 넘는 협업을 위한 문서관리 중심으로 기획되었다.

### 사용자 문제
국경을 넘어 협업하는 팀, 특히 사전에 구조화된 글로벌 협업 워크플로우가 없는 비정형 팀은 서로 다른 언어로 인한 번역 오류, 국가·팀마다 다른 협업 문화(초안 공유 시점, 의사결정 속도, 피드백 방식)의 충돌, 시차로 인한 답변 대기·리뷰 지연·인수인계 부족, 여러 조직이 얽힐 때 결정권자·리뷰어·책임자가 불명확한 문제를 동시에 겪는다. 또한 문서가 제약 없이 바로 수정되면서 잘못된 내용이 반영되거나 기존 결정이 훼손되는 문제도 있다.

### 해결 방안
첫 결과물은 문서를 코드처럼 관리하는 Doc PR(작성 → PR 생성 → AI 리뷰 → 사람 리뷰 → Merge) 워크플로우에 집중한다. AI Writing Assistant가 작성 중 문서 구조와 맥락을 돕고, Document Graph가 문서 관계와 변경 영향을 보여주며, DocumentLion이 문서 충돌·정합성·협업 규칙 위반을 검토하고, Dev-aware Translation이 개발 요소를 보존한 번역으로 언어 장벽을 낮춘다. 이 네 핵심 기능을 AI CIO가 명령·수행·결재 구조로 조율하며, Team Collaboration Charter·Follow-the-Sun 워크플로우·RACI 역할 추천의 자동 추천·분석·설정은 후속 단계 범위로 둔다.

### 차별점
다른 협업 도구들이 기능별로 AI를 개별적으로 붙이는 것과 달리, 이 서비스는 팀의 문서 전체·문서 간 관계·팀원의 관여 이력이라는 단일 데이터 기반 위에서 하나의 AI(CIO)가 핵심 기능의 판단 근거가 되는 구조다. 첫 결과물에서는 DocumentLion, AI Writing Assistant, Dev-aware Translation이 CIO에게 명령을 받아 수행하고 다시 CIO의 결재를 받으며, Document Graph가 이 기능들이 공유하는 문서 관계·영향 데이터를 제공한다. 원래 대기업 정도에나 있는 CIO(정보관리책임자) 역할을 학생 팀과 같이 구조화되지 않은 팀도 AI를 통해 가질 수 있게 한다.

## 1. 문화 보더 해소
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

국가·팀마다 다른 협업 방식(초안 공유 시점, 의사결정 속도, 피드백 방식)의 충돌을 막기 위해 AI가 팀원의 협업 방식을 분석해 협업 규칙을 제안하고, 팀이 이를 공식 규칙으로 채택하는 영역이다.

**수용 기준:**
```
1. ○ AI는 팀원들의 협업 방식을 분석해 협업 규칙 초안을 생성한다.
2. ○ 팀은 생성된 규칙 초안을 수정해 프로젝트 공식 규칙으로 채택할 수 있다.
3. ○ 채택된 협업 규칙은 DocumentLion의 결재 기준(협업 규칙 위반 여부 판단)에 사용된다.
```


### 1.1 Team Collaboration Charter
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

팀의 협업 방식에 맞는 협업 규칙을 관리하고 DocumentLion의 검토 기준에 연결하는 기능이다. 첫 결과물에서는 규칙 예시를 Doc PR 리뷰 근거로 보여주며, 팀이 규칙을 수정해 확인할 수 있다. 팀원 행동 분석을 통한 규칙 초안 생성과 자동 갱신은 후속 단계 범위로 둔다.


#### 1.1.1 협업 규칙 초안 생성

AI가 팀원들의 협업 방식(초안 공유 시점, 응답 속도, 피드백 방식 등)을 분석해 팀 협업 규칙 초안을 자동으로 생성하는 동작이다. 팀 생성 초기 시점에 한 번 트리거되는 분석·생성 동작이다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중


#### 1.1.2 협업 규칙 수정·채택

팀이 AI가 생성한 협업 규칙 초안을 직접 수정하고 프로젝트의 공식 규칙으로 확정하는 동작이다. 확정된 규칙은 이후 DocumentLion의 결재 기준으로 사용된다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

## 2. 지리 보더 해소
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

시간대가 다른 팀원 간 답변 대기, 리뷰 지연, 업무 인수인계 부족 문제를 해결하기 위해 팀원이 동시에 존재하지 않아도 프로젝트가 계속 진행되도록 다음 작업자를 추천하는 영역이다.

**수용 기준:**
```
1. ○ 시간대, 담당 역할(RACI), 현재 업무량, 프로젝트 상황을 고려해 다음 작업자를 추천한다.
2. ○ 다음 작업자 후보 중 해당 문서와 연결된 다른 문서에 대한 최근 관여도가 높은 사람이 우선 추천된다.
```


### 2.1 Follow-the-Sun 워크플로우
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

시간대와 문서 맥락을 바탕으로 다음 작업자를 이어 주는 기능이다. 첫 결과물에서는 Doc PR에 다음 작업자가 필요한 상태와 인수인계 정보가 연결될 위치를 보여준다. 업무량·시간대·문서 관여 이력을 분석한 자동 작업자 추천은 후속 단계 범위로 둔다.

## 3. 조직 보더 해소
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

여러 회사·팀이 함께 일할 때 결정권자, 리뷰어, 책임자가 불명확하거나 정보가 의도치 않게 노출되는 문제를 해결하기 위해 문서와 Doc PR마다 RACI 역할과 공개 범위를 정의하는 영역이다. 팀 관리자는 R/A/C/I 역할과 지정 참여자를 직접 지정하며, 역할별 문서·Doc PR·검토 근거 접근 범위는 아래와 같다.

| 역할 | 열람 범위 | 허용 행동 | 숨김 대상 |
| --- | --- | --- | --- |
| R | 자신이 맡은 초안·반려 Doc PR과 관련 공식 문서 | 작성, 수정, 재제출 | 다른 참여자의 비공개 Doc PR, 예외 Merge 사유 |
| A | 자신에게 배정된 Doc PR과 관련 공식 문서·검토 근거 | 승인, 반려, 예외 Merge 및 사유 기록 | 권한 없는 지정 참여자 전용 문서 |
| C | 자신에게 배정되어 검토 중인 Doc PR과 관련 공식 문서 | 리뷰 의견 등록 | 초안, 반려된 Doc PR, 예외 Merge 사유 |
| I | 열람 권한이 있는 Merge 완료 공식 문서 | 열람 | 모든 초안·Doc PR·검토 근거·예외 Merge 사유 |

지정 참여자 전용 문서는 RACI 참여자와 팀 관리자만 열람할 수 있고, 자동 권한 조정은 후속 단계 범위로 둔다.

**수용 기준:**
```
1. ○ 팀 관리자는 문서 또는 Doc PR마다 R/A/C/I 역할과 지정 참여자를 직접 지정하고 변경할 수 있다.
2. ○ R 역할은 자신이 맡은 초안과 반려 Doc PR을 작성·수정·재제출할 수 있고, A 역할만 자신에게 배정된 Doc PR을 승인하거나 예외 Merge 사유를 기록할 수 있다.
3. ○ C 역할은 자신에게 배정되어 검토 중인 Doc PR에만 리뷰 의견을 등록할 수 있으며, 초안·반려된 Doc PR과 예외 Merge 사유는 열람할 수 없다.
4. ○ I 역할은 열람 권한이 있는 Merge 완료 공식 문서만 열람할 수 있고, 모든 초안·Doc PR·검토 근거·예외 Merge 사유는 표시되지 않는다.
```

## 4. 언어 보더 해소
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

서로 다른 모국어를 쓰는 팀원 간 번역 오류와 의사소통 지연을 줄이기 위해, 코드·기술 용어 같은 개발 요소를 보존하면서 문서를 번역해 제공하는 영역이다. 문서 작성 언어와 열람 언어가 달라도 팀원이 내용을 정확히 이해할 수 있도록 돕는 데 집중하며, 실시간 음성 통역 등 비문서 커뮤니케이션은 범위 밖이다.

**수용 기준:**
```
1. ○ 팀원은 문서를 자신이 선호하는 언어로 번역해 열람할 수 있다.
2. ○ 번역 시 코드 블록, 기술 용어, 고유명사(문서/기능/변수명 등)는 원문 그대로 보존된다.
```


### 4.1 Dev-aware Translation
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

팀원이 문서를 자신의 언어로 번역해 열람하도록 돕는 기능이다. 코드 블록, 기술 용어, 고유명사를 보존한 번역을 제공해 개발 맥락이 왜곡되지 않도록 하며, 실시간 음성 통역이나 채팅 등 비문서 커뮤니케이션 번역은 범위 밖이다.

**개발 준비 슬롯**
- **선행조건**: - 번역 대상 문서는 현재 사용자가 열람 권한을 가진 공식 문서 또는 Doc PR 초안이어야 한다.
- **트리거**: - 팀원이 문서 열람 화면에서 번역 언어를 선택하면 번역이 실행된다.
- **동작**: - AI가 원문을 대상 언어로 번역하면서 코드 블록, 기술 용어, 고유명사(문서명·기능명·변수명 등)는 원문 그대로 유지한다.
- **결과**: - 번역된 문서가 화면에 표시된다.
- **표시**: - 번역본에는 AI 번역임을 알리는 라벨이 함께 표시된다.
- **권한 & 접근**: - 해당 문서에 대한 열람 권한이 있는 사용자만 번역을 요청할 수 있다.

## 5. AI 문서 작성·리뷰 지원
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

Code PR의 정적 분석·CI 검사가 코드 품질을 1차로 걸러주듯, 문서 작성 중 구조/맥락을 보조하고 Doc PR 제출 시 AI가 먼저 문서 충돌·정합성·협업 규칙 위반을 검토해 사람 리뷰어의 부담을 줄이는 영역이다. AI의 판단은 참고용 1차 검토이며, 최종 승인·반려 결정은 여전히 사람 리뷰어(A 역할)가 내린다.

**수용 기준:**
```
1. ○ 팀원은 문서 작성 중 AI로부터 구조 개선, 다음 내용 제안 등 작성 보조를 받을 수 있다.
2. ○ Doc PR이 제출되면 AI가 문서 충돌·정합성·협업 규칙(Charter) 위반 여부를 자동 검토하고 그 근거를 함께 제공한다.
3. ○ AI 검토 결과는 사람 리뷰어의 승인/반려를 대체하지 않고 리뷰 화면에 참고 정보로 표시된다.
```


### 5.1 AI Writing Assistant
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

팀원이 문서를 작성하는 동안 AI가 구조 개선, 누락된 내용, 다음 문단 제안 등을 실시간으로 보조하는 기능이다. 제안은 참고용이며 수락 여부는 전적으로 작성자가 결정하며, AI가 문서를 대신 완성하는 자동 생성은 범위 밖이다.

**개발 준비 슬롯**
- **선행조건**: - 팀원이 문서 초안을 작성하거나 수정 중인 상태여야 한다.
- **동작**: - AI가 현재까지 작성된 내용과 문서 맥락을 분석해 구조 개선, 누락 항목, 다음 내용 제안을 생성한다.
- **결과**: - 작성자가 제안을 수락하면 해당 내용이 문서에 반영되고, 거부하면 문서는 변화 없이 유지된다.
- **예외**: - AI가 제안을 생성하지 못하는 경우(내용 부족 등) 제안 없이 작성을 계속할 수 있다.
- **표시**: - 제안은 본문과 구별되는 패널/인라인 형태로 표시된다.
- **권한 & 접근**: - 해당 문서의 작성·수정 권한이 있는 사용자만 AI 제안을 받을 수 있다.
- **비즈니스 규칙**: - AI는 문서를 대신 완성하거나 자동 저장하지 않고, 모든 반영은 작성자의 명시적 수락을 거쳐야 한다.


### 5.2 DocumentLion
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

Doc PR이 제출되면 AI가 문서 충돌, 정합성, 협업 규칙(Charter) 위반 여부를 자동으로 1차 검토해 근거와 함께 리뷰어에게 제공하는 기능이다. 최종 승인·반려 권한은 여전히 사람 리뷰어(A 역할)에게 있으며, AI의 판단은 그 결정을 대체하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 검토 대상은 생성되어 리뷰 대기 상태인 Doc PR이어야 한다.
- **트리거**: - 팀원이 Doc PR을 제출(생성 또는 재제출)하면 AI 검토가 자동으로 실행된다.
- **동작**: - AI가 Doc PR의 변경 내용을 기존 공식 문서 및 연결 문서와 비교해 충돌·정합성 문제를 탐지하고, 채택된 협업 규칙에 비춰 규칙 위반 여부를 판단한다.
- **결과**: - 검토 결과(문제 없음/주의/반려 권장 등)와 근거가 Doc PR 리뷰 화면에 기록된다.
- **예외**: - AI 검토 자체가 실패하더라도 Doc PR은 사람 리뷰 단계로 진행될 수 있으며, 검토 미수행 상태임을 리뷰어에게 알린다.
- **표시**: - 검토 결과는 Doc PR 리뷰 화면에서 변경된 문서와 함께 확인할 수 있다.
- **권한 & 접근**: - 해당 Doc PR의 리뷰어(C·A 역할)만 AI 검토 결과를 열람할 수 있다.
- **비즈니스 규칙**: - AI의 검토 결과는 참고용이며, Doc PR의 승인·반려는 오직 사람 리뷰어(A 역할)가 결정한다.
