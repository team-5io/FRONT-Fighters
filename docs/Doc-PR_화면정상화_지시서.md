# Doc PR — 화면 정상화(재건축) 작업 지시서

> 이 문서는 코딩 에이전트(Claude Code 등)에게 그대로 붙여넣어 작업을 지시하기 위한 문서다.
> 대상 저장소: 20개 화면이 Figma를 픽셀 단위로 그대로 옮겨 이미 구현된 상태.

---

## 0. 배경과 목표

1차 구현은 **Figma 좌표를 그대로 재현하는 데만 집중**했고, 그 결과 다음이 그대로 화면에
남았다: 빈 상태(empty state) 미처리, AI 판단과 사람 판단의 시각적 미분리, 라벨 복붙 오류,
같은 개념의 표기 불일치, 화면마다 다른 상태값 체계, 디자인 시스템과 반대로 매핑된 RACI
색상, 필수 요구사항(AI 번역 라벨 등) 누락. 이 지시서는 이미 구현된 20개 화면을
**프로덕트 기획(기능명세서·유저플로우) 기준으로 재건축**하는 것이 목적이다.

**한 줄 정체성**: 노션(문서/워크스페이스 경험) + GitHub(PR 워크플로우) + CodeRabbit(AI
1차 리뷰)을 통폐합한 팀 문서 협업 툴.

**범위 — 반드시 지킬 것**
- ✅ 화면(프론트엔드) 구현 정상화만 한다.
- ❌ API 연동/실제 네트워크 호출 금지. 지금 쓰는 로컬 mock/정적 데이터 구조를 유지한다.
  단, mock 데이터의 **필드명·상태값·엔티티 구조**는 첨부된 API 명세서를 기준으로 맞춘다
  (아래 6장).
- ❌ 기능명세서에 없는 기능을 새로 만들지 않는다. 없는 기능은 "후속 단계 범위"로 화면에
  명시하거나 비활성 처리한다.

---

## 1. 판단 기준 우선순위 (문서 간 충돌 시)

1. **`기능명세서.md`** — 무엇을 해야 하는가(요구사항, 권한, 표시 규칙, 수용 기준)
2. **`유저플로우.md`** — 화면 간 이동 구조, 진입점, 어떤 화면이 어떤 화면을 여는지
3. **본 지시서 3장(노션 스타일 구조 적용 방식)**
4. **`DESIGN.md`** — 색상/타이포/라운드/스페이싱 토큰. 색상 테마는 **변경 금지** (아래 3장 참고)
5. **`2차-UX-패스-체크리스트.md`** — 화면별로 구체적으로 무엇이 고장났는지의 실측 목록.
   여기 적힌 항목은 전부 해소 대상이다.
6. **`화면-목록.md`** — 라우트 ↔ 소스파일 대응표, 기존에 교정한 오탈자 목록(되돌리지 말 것)
7. Figma는 더 이상 기준이 아니다. 픽셀 좌표 재현보다 정보구조 정상화가 항상 우선한다.

## 2. 화면에 반영해야 할 제품 정체성

- **CIO 단일 AI 정체성**: AI Writing Assistant · DocumentLion · Dev-aware Translation은
  전부 하나의 AI(CIO, 정보관리책임자)가 수행한다. 화면에 노출되는 모든 AI 산출물은
  **동일한 CIO 배지/아이콘/톤**으로 통일해서 표시한다. 서로 다른 기능인데 서로 다른 AI가
  일하는 것처럼 보이면 안 된다.
- **명령·수행·결재 구조**: AI의 모든 판단은 "1차/참고"이고 최종 결정은 항상 사람(A 역할)의
  몫이다. 이 위계가 화면에서 항상 보여야 한다 — 2차 체크리스트의 "AI/사람 리뷰 분리(원칙 3)"
  항목이 이것의 구체 사례다.
- **Doc PR = 코드 PR의 문서판**: 상태 파이프라인(초안 → PR 생성 → AI 리뷰 → 사람 리뷰 →
  Merge), 변경 비교(diff에 준하는 문서 변경 비교), 리뷰어/승인자 배지, Merge 차단 사유
  체크리스트 등 GitHub PR 사용자가 익숙한 개념 지도를 문서 버전으로 그대로 노출한다.
- **DocumentLion = CodeRabbit류 AI 1차 리뷰**: 이슈 지적 + 근거 구조로, 비침습적인
  "보조자" 톤을 가져야 한다. 사람 리뷰와 뚜렷이 다른 카드/톤으로 분리한다.
- **문서 작성/열람 = 노션 페이지 경험**: 절제된 크롬, 넓은 캔버스, 문서 자체가 주인공.

## 3. "노션 구조를 따른다"의 구체적 의미

**중요한 전제**: 첨부된 `NOTION_DESIGN.md`는 노션의 **마케팅 사이트/Help 문서 크롬**을
스크래핑한 실측 데이터이며, 로그인 후 실제 워크스페이스 UI(사이드바, 블록 에디터,
데이터베이스 표)는 포함하지 않는다. 따라서 이 파일에서 **그대로 가져올 것**과
**가져오지 말 것**을 구분한다.

### 가져오지 말 것
- 색상 토큰(`#0075de` 등 노션 블루). **Doc PR 브랜드 컬러(`main-500 #9000FF` 등,
  `DESIGN.md` 2장)를 그대로 유지**한다. 색상 테마 교체는 이 작업의 범위가 아니다.
- 노션 전용 폰트(NotionInter) 자체 — Doc PR은 Pretendard/JetBrains Mono(`DESIGN.md` 3장)를 유지한다.

### 가져올 것 (톤·리듬)
- 여백 리듬 4/8/12/16/24px, 카드 12px 라운드 + 1px 옅은 보더(`rgba(0,0,0,0.1)` 급) +
  그림자 없는 플랫함, 절제된 타이포 위계, 담백하고 사용자 언어 중심의 카피 톤
  (`DESIGN.md` 1장에 이미 명시: "웹훅 설정"이 아니라 "팀원 관리").
- `NOTION_DESIGN.md`가 다루지 않는 워크스페이스 UI(사이드바, 페이지, 표 뷰)는 **일반적으로
  잘 알려진 노션 앱의 구조 관용구**를 적용한다(실측 근거가 아닌 통상적 패턴 적용임을
  인지하고 진행):
  - **좌측 고정 사이드바**: 팀/워크스페이스 표시 → 최상위 섹션(문서 / Doc PR / Document
    Graph / 설정)을 페이지 트리처럼 배치 → 하단에 설정·멤버 진입점.
  - **문서 상세/작성 화면 = "페이지"**: 상단 브레드크럼(팀 > 상위 문서 > 현재 문서),
    제목은 크고 인라인 편집 가능한 형태, 본문은 넓은 단일 컬럼, 메타데이터(작성자·상태·
    RACI·최근 수정)는 제목 바로 아래 얇은 속성(property) 줄로.
  - **목록형 화면(문서 목록 / Doc PR 목록 / 팀 용어집)**: 노션 데이터베이스 "표" 뷰처럼 —
    고정 헤더 행, 행 hover 시 옅은 강조, 상태는 컬러 태그(pill), 필터/정렬 바는 표 위에.
  - **모달보다 사이드 패널/인라인 확장을 우선**한다.
- 결과적으로 1차 구현의 "각 잡힌 대시보드 카드 그리드" 톤에서
  **"문서/페이지 중심의 조용한 캔버스" 톤**으로 전환하는 것이 이 장의 핵심이다.

## 4. 반드시 해소해야 하는 결함 (2차-UX-패스-체크리스트.md 요약)

아래는 체크리스트 원문의 요약이다. **작업 시 반드시 원문(`2차-UX-패스-체크리스트.md`)을
직접 열어 세부 좌표·근거까지 확인할 것** — 이 표는 누락 방지용 색인이다.

| 영역 | 문제 | 조치 방향 |
|---|---|---|
| AI/사람 리뷰 분리 (원칙 3) | 대시보드 통계 카드 4개가 동일 톤 — AI 반려도 승인 완료와 동급으로 보임 | AI 계열 지표를 별도 그룹/라벨("AI 1차 검토")로 분리 |
| " | Merge 차단 사유 목록에 AI/사람/시스템 사유가 섞여 있음 | 주체별 색·라벨 구분 + AI 항목엔 "참고용, 최종 결정은 A 역할" 안내 |
| " | Doc PR 상세: AI/사람 카드는 분리됐지만 안내 문구가 없음 | 안내 문구 추가, 이 화면의 분리 방식을 기준선으로 다른 화면에 적용 |
| " | 최근 활동 목록에서 AI/사람 항목이 같은 형식 | 주체 라벨/아이콘 추가 |
| 빈 상태 (원칙 4) | 팀 초대의 `플랜` 값 빈칸, 문서 목록 본문 전부 스켈레톤, 협업 규칙 3장 전부 빈 초안, 팀 용어집 표 5행 전부 빈 상태 — 로딩/데이터없음 구분 불가 | 원칙 4(시스템 목소리로 왜 비어있는지 + 다음 행동 안내) 적용, 실제 빈 상태 컴포넌트 도입 |
| 팀원 관리 라벨 오류 | 대체 승인권자 카드의 입력 2개 라벨이 둘 다 `원문 (Source)` (용어집 라벨 복붙) | `대체 승인권자 선택` / `지정 사유 (선택)`로 정정, 승인권자 지정 화면과 표기 통일 |
| " | 화면이 팀 관리자만 가능하다고 안내하지만 현재 사용자의 권한 여부 표시가 없음 | 권한 표시 추가 |
| 표기 통일 | `승인 권자` vs `승인권자` 혼용 | 한쪽으로 확정 후 전 화면 통일 |
| 협업 규칙 채택 동작 부재 | 배지가 `초안-미채택`, 안내는 "공식 채택하세요"인데 채택 버튼이 없음 | 채택 버튼/권한/재채택 동작을 정의하고 구현 |
| 번역/다국어 표시 (원칙 5) | 번역 보기에 필수인 "AI 번역" 라벨 없음, 원문 전환 동작 없음, 다른 화면엔 번역본 표기 자체가 없음 | 라벨 추가(필수), 원문⇄번역 전환 동작 추가, 목록 화면 번역본 표기 정의 |
| RACI 색 불일치 | Figma가 R/A를 뒤바꿔 사용 — 가장 강한 권한(A)의 색이 화면마다 다름 | `CLAUDE.md`/`DESIGN.md` 규칙(R=info·A=main·C=warning·I=neutral)로 통일, `RaciChip` 공용 컴포넌트로 색 규칙 일원화 |
| RACI 가시성 (원칙 2) | 구현된 화면 어디에도 "현재 사용자의 RACI 역할·가능 행동"이 안 보임 | 기능명세서 3장 권한 매트릭스 대조해 역할별 노출/숨김 정리, 특히 팀 설정 초기화(A 전용)·RACI 역할 관리·Doc PR 목록 역할 필터에 반영 |
| 상태 배지 규칙 | 반려 배지만 테두리 규칙이 다름, 동일 글자수인데 폭 다름, 화면마다 상태값 체계 자체가 다름(문서 목록: 공식/초안/리뷰중 vs Doc PR 목록: 승인대기/AI리뷰중/반려/재제출/확정/검토대기/리뷰어지정필요) | 기능명세서 상태 정의(draft/review/merged/rejected)와 대조해 **공용 상태 집합 + Badge 컴포넌트**로 통일 |
| 디자인 시스템 스냅 문제 | 회색 칩(`#EDEDED`)과 카드 배경(`#FBFBFB`)이 둘 다 `neutral-50`으로 뭉개짐 | 토큰 재검토 |
| 프레임 간 불일치 | 사이드바 폭/선택 칩 위치/목록 행 피치가 프레임마다 미세하게 다름 (이미 공용 컴포넌트로 흡수됨) | 유지, 디자인 확정 시 어느 값이 맞는지만 재확인 |

## 5. 화면별 작업 지시 (20개)

`화면-목록.md`의 라우트 표를 기준으로 한다. 표에 없는 새 라우트/파일 추가 금지. 진행하며
라우트가 바뀌면 `화면-목록.md`도 갱신한다.

### A. 인증/온보딩 — `#/login`, `#/team-invite`, `#/team-reset`
- 기능적으로 큰 문제는 없음. `팀 초대`의 `플랜` 빈칸을 4장 빈 상태 원칙에 맞게 처리.
- 노션 톤 적용: 카드 톤을 절제되게, 과한 장식 제거.

### B. 대시보드(홈) — `#/dashboard`
- 통계 카드 4개 중 `AI 반려`만 AI 판단 — 시각적으로 분리(그룹핑 또는 "AI 1차 검토" 라벨).
- Merge 차단 사유 목록 — 주체(AI/사람/조직/시스템)별 구분 + AI 항목에 참고용 안내.
- 최근 Doc PR 활동 — AI/사람 항목 라벨·아이콘으로 구분.
- 상태 배지는 5장 공용 Badge 체계 적용.

### C. 문서 목록 — `#/documents`
- 본문 텍스트 스켈레톤 상태를 실제 빈 상태/데이터로 정리(원칙 4). 문서 상태값을
  기능명세서 상태 정의로 통일.
- 노션 표 뷰 톤: 헤더 고정, hover 강조, 필터바 위치.

### D. Doc PR 목록 — `#/doc-pr`
- 상태값 7종을 공용 상태 집합(Badge 컴포넌트)으로 재정의. `반려` 배지 테두리 규칙 통일
  (이미 1차에서 처리됨 — 회귀 주의).
- "내 역할" 표시 부재 — RACI 가시성 원칙 적용해 역할 필터 옆에 "내 역할" 노출.

### E. Document Graph — `#/graph`
- `[비공개 문서]` 권한 안내 문구가 상세 화면 안내와 어긋나는 부분 확인 후 통일 여부 결정.
- 그래프 자체는 Document Graph가 DocumentLion 등 기능의 **기반 인프라**임을 시각적으로도
  느껴지게(다른 기능에서 그래프 데이터를 인용하는 지점과 연결감 있게) 구성.

### F. 문서 작성/편집 — `#/write`, `#/ai-structure`, `#/link-documents`
- AI 구조 추천 결과는 CIO 배지로 통일. 스켈레톤 본문 실제 상태로 정리.
- 노션 페이지 톤 핵심 적용 지점 — 넓은 단일 컬럼, 속성 줄, 절제된 크롬.

### G. 번역 보기 — `#/translation`
- **"AI 번역" 라벨 필수 추가**(기능명세서 4.1 표시 규칙, 현재 누락 — 최우선 처리).
- 원문 ⇄ 번역 전환 동작 추가(현재 좌우 병렬만 가능).
- 저장 버튼 라벨(`연결 저장`)이 다른 화면에서 복붙된 오류 — 정정.
- 문서 목록/Doc PR 목록 등 다른 화면에도 번역본 존재 표기를 정의해 추가.

### H. Doc PR 상세 — `#/doc-pr-detail`
- AI/사람 리뷰가 카드로는 분리돼 있으나 "참고용, 최종 결정은 A 역할" 안내 누락 — 추가.
  이 화면의 분리 방식을 다른 화면(대시보드·목록)의 기준선으로 삼는다.
- Merge 조건 체크에서 AI 리뷰 완료(AI)와 사람 리뷰 완료(사람)가 동일 배지·톤 — 구분.

### I. AI 리뷰 결과 — `#/ai-review`
- ⚠️ 사이드바 선택이 `설정`으로 돼 있음 — Doc PR 상세에서 들어오는 화면이므로 `Doc PR`로
  정정(원본 확인 필요 항목이었으나, 유저플로우 기준(`n23 → n51`)으로는 Doc PR 계열이 맞음).
- CIO 배지 통일 적용.

### J. 사람 리뷰 — `#/human-review`
- 샘플 데이터 불일치(작성자/처리 이력/승인자 인물이 서로 안 맞음) — mock 데이터 정합성 수정.
- 카드 제목 `Doc PR 콘테스트` → `컨텍스트`로 추정 수정 여부 결정(문맥상 오탈자 가능성 높음).

### K. 승인권자 지정 — `#/assign-approver`
- `지정 조건 안내` 패널 테두리를 다른 안내 패널과 통일(`main-500/20`).
- 팀원 관리 화면과 기능 중복(대체 승인권자 지정) — 팀 단위 vs Doc PR 단위 관계 정리 후
  중복이면 한쪽으로 흡수.

### L. 팀 설정/관리 — `#/settings`
- 팀 정보 카드 위 섹션 라벨이 `문서 제목`으로 오기 — `팀 정보`로 정정(원본유지 판단 재검토
  대상, 명백한 라벨 복붙 오류로 판단됨).

### M. RACI 역할 관리 — `#/raci-roles`
- **RACI 색상 반전 수정 최우선**: R=info·A=main·C=warning·I=neutral(`DESIGN.md` 규칙)로
  전 화면 통일. `src/components/ui/RaciChip.jsx` 신설해 4곳에 흩어진 색 배열을 한 곳으로.
- 이 화면 자체에 대한 권한 표시 부재 — 팀원 전원 역할을 바꾸는 민감한 화면이므로
  "팀 관리자만 가능" 안내와 현재 사용자 권한 표시 추가, C·I 역할 진입 시 읽기 전용 처리.

### N. 협업 규칙(Charter) — `#/charter`
- **채택(공식 확정) 버튼/동작 추가** — 현재 `취소`/`변경 사항 저장`만 있어 `미채택` 상태를
  벗어날 방법이 없음. 채택 권한 역할, 재채택 시 적용 시점 안내와 실제 동작을 맞춘다.
- 규칙 3장 빈 초안 상태 — 원칙 4에 따라 실제 빈 상태 문구로 정리.

### O. 팀 용어집 관리 — `#/glossary`
- 표 5행 전부 빈 상태 — "아직 등록된 용어가 없습니다 + 용어 추가로 유도" 안내 추가(원칙 4).
- 타이틀 `팀 설정` 오기 여부 재검토(용어집 화면인데 팀 설정으로 표기됨 — 명백한 오류 가능성).
- 페이지네이션 단일 페이지 표시 정리.

### P. 팀원 관리 — `#/team-members`
- **라벨 복붙 오류 수정 최우선**: 대체 승인권자 카드 입력 2개가 둘 다 `원문 (Source)` →
  `대체 승인권자 선택` / `지정 사유 (선택)`로 수정.
- 팀 관리자 권한 여부 표시 추가.
- 타이틀 `팀 설정` 오기 재검토(용어집과 동일 패턴).

## 6. 데이터/상태 정합성 (API 명세서 기반 — UI 구조만 반영, 연동은 하지 않음)

첨부 API 명세서(`API_명세서_*.csv`)의 엔드포인트·역할·엔티티를 화면의 mock 데이터
구조와 상태값 이름의 **기준선**으로만 사용한다. 실제 fetch/axios 호출은 작성하지 않는다.

- **Doc PR 상태 파이프라인**: `GET /doc-prs/{prId}` 설명에 명시된 상태 =
  생성 / AI리뷰 / 사람리뷰 / 반려 / 재제출 / 확정 / 리뷰어지정필요. 화면마다 제각각인
  배지 문구(공식/초안/리뷰중, 승인대기/AI리뷰중/반려/재제출/확정/검토대기/리뷰어지정필요)를
  이 상태 집합 하나로 수렴시키고 공용 `Badge`/`StatusBadge` 컴포넌트로 관리한다.
- **RACI 권한**: `GET /documents/{documentId}/my-permissions`가 "이 결과를 모든 API가
  공통으로 적용한다"고 명시 — 즉 **화면에도 항상 "내 권한" 개념이 노출돼야 한다**는 뜻으로
  해석해 5장의 RACI 가시성 조치에 반영한다. 기능명세서 3장의 R/A/C/I 열람범위·허용행동·
  숨김대상 표를 각 화면 조건 분기의 근거로 사용한다.
- **Merge 차단 사유**: `GET /doc-prs/{prId}/merge-check` 설명("DocumentLion반려·리뷰미완료·
  승인권자부재·충돌미해결")을 대시보드/상세 화면의 차단 사유 목록 항목과 1:1로 맞춘다.
- **AI 관련 엔드포인트는 전부 `AI(CIO)` 계층으로 명시**돼 있음 — 화면에도 이 CIO 단일
  주체 표기를 일관 적용한다(2장 참고).
- **프론트엔드에 노출하지 않는 항목**: "내부 로직(프론트엔드 미노출)"로 표시된 CIO 2차
  검토, AI 기능 실행 명령 전달, 그리고 "내부 이벤트(엔드포인트 없음)"인 알림 생성류는
  화면에 별도 UI로 노출하지 않는다(알림 목록 조회 `GET /notifications` 결과를 보여주는
  것과는 별개).
- **번역**: `POST /documents/{documentId}/translations`의 설명("코드블록·API명·변수명은
  보존") — Dev-aware Translation 관련 화면의 원문 보존 표시 로직 근거로 사용.

## 7. 작업 방식

1. **공용 컴포넌트/토큰 정리를 가장 먼저 한다** (다른 화면 작업의 전제):
   - `StatusBadge`(Doc PR/문서 상태 통일), `RaciChip`(색 규칙 일원화), `EmptyState`
     (원칙 4 공용 처리), `AiReviewCard` / `HumanReviewCard`(원칙 3 — CIO 배지 + "참고용,
     최종 결정은 A 역할" 안내를 내장한 래퍼).
2. **진행 순서 제안**:
   1. 공용 컴포넌트/토큰
   2. 목록형 화면(대시보드, 문서 목록, Doc PR 목록) — 노션 표 뷰 톤 적용
   3. 문서 작성/번역/AI 리뷰 — 노션 페이지 톤 적용
   4. 리뷰/승인 플로우(Doc PR 상세, 사람 리뷰, 승인권자 지정)
   5. 설정/RACI/Charter/용어집/팀원 관리
3. **mock 데이터**: 로컬 상수/state 유지. API 호출 코드를 작성하지 않는다. 다만 6장 기준에
   맞춰 필드명·상태값을 정리한다.
4. **컴포넌트 재사용 우선**: `src/components/ui`의 기존 컴포넌트를 확장하고, 새 컴포넌트가
   필요하면 `DESIGN.md` 토큰만 사용한다(`doc-pr-design-system.jsx` 기존 구현 참고).
5. 화면 하나를 마칠 때마다 **4장 표에서 해당 화면의 항목이 실제로 해소됐는지 자체 점검**
   후 다음 화면으로 넘어간다.
6. 완료 후 `화면-목록.md`를 갱신하고, 프로젝트에 `CLAUDE.md`가 있다면 새로 확정된 규칙
   (상태 배지 체계, RACI 색, AI/사람 분리 컴포넌트 규칙 등)을 반영한다.

## 8. 완료 기준 (Definition of Done)

- [ ] 모든 화면에서 AI 산출물과 사람/시스템 상태가 시각적으로 구분되고, AI 항목엔
      "참고용, 최종 결정은 A 역할" 안내가 붙는다.
- [ ] Doc PR/문서 상태 배지가 화면 전체에서 하나의 체계로 통일돼 있다.
- [ ] RACI 색이 `DESIGN.md` 규칙(R=info·A=main·C=warning·I=neutral)으로 전 화면 통일돼 있다.
- [ ] 모든 빈 상태가 "무엇이 왜 비었는지 + 다음 행동"을 안내한다(로딩과 구분됨).
- [ ] 번역 보기에 "AI 번역" 라벨이 있고 원문 전환이 가능하다.
- [ ] 협업 규칙(Charter) 화면에서 초안을 실제로 채택할 수 있다.
- [ ] 라벨 복붙 오류(팀원 관리의 `원문 (Source)` 등)가 모두 정정됐다.
- [ ] 사이드바/문서 페이지/목록 화면이 3장에서 정의한 노션 톤(여백 리듬, 플랫 카드, 표 뷰,
      절제된 카피)을 따르되 Doc PR 브랜드 컬러(`main-500` 등)는 그대로 유지한다.
- [ ] API 호출 코드가 추가되지 않았다(mock 데이터만 사용).
- [ ] `화면-목록.md`가 최신 상태를 반영한다.
