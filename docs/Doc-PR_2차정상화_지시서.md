# Doc PR — 2차 정상화 지시서

> `normalization_v1.md` 이후 작업. 1차가 만든 데이터/컴포넌트 단일 출처
> (`src/data/status.js`, `src/data/raci.js`, `StatusBadge`, `RaciChip`, `CioBadge`,
> `AiDisclaimer`, `AiReviewCard`/`HumanReviewCard`, `EmptyState`, `DataTable`, `MyRoleBar`,
> `Page`/`PageHeader`/`Section`, `Card`, `tone.js`)는 **그대로 재사용**하고, 그 위에 이번
> 4가지를 얹는다. 1차 산출물을 갈아엎지 않는다 — 부족한 부분만 이어서 짓는다.

---

## 0. 이번 작업의 성격

1차는 "고장난 걸 고치는" 작업이었다면, 2차는 **"기능은 맞는데 경험이 아직 노션이 아닌"**
지점을 고친다. 1차 결과서 5장(화면별 변경)이 스스로 인정한 지점이 출발점이다 — 문서
작성은 여전히 자유 텍스트 입력이고, AI 제안은 별도 화면(`#/ai-structure`)으로 빠져
있고, Document Graph는 노드 관계를 카드/목록에 가깝게 보여주고 있고, 화면 전체가
카드를 켜켜이 쌓아 올린 형태다. 넷 다 "기능은 구현됐지만 노션 같지 않다"는 같은 문제의
다른 얼굴이다.

**범위는 1차와 동일하다**: 화면(프론트엔드) 구현만. API 연동 금지, mock 데이터 유지,
기능명세서에 없는 기능을 새로 만들지 않는다.

**참고 문서 우선순위는 1차 지시서 1장과 동일**하되, 이번엔 `NOTION_DESIGN.md`를
실제로 열어서 대조한다 — 1차 결과서 6장이 지적했듯 1차 작업 시점엔 이 파일이 리포에
없어 일반 지식으로만 진행했다. 다만 그 파일은 **노션 마케팅 사이트/Help 크롬 스크래핑
데이터**이지 로그인 후 워크스페이스 UI(에디터·사이드바·그래프)의 실측이 아니라는
전제는 1차와 동일하게 유지한다. 즉 이번에 새로 만드는 블록 에디터/AI 패널/그래프 뷰는
`NOTION_DESIGN.md`의 색·여백·타이포 토큰과는 대조하되, 구조 자체는 노션·옵시디언 같은
실제 제품에 대한 통상적 지식으로 설계한다는 점을 인지하고 진행한다.

## 1. 문서 작성 — 계층형 블록 마크다운 에디터

현재 `#/write`(`DocumentWritePage`)는 자유 텍스트 입력창이다. 이걸 **노션과 동일한
블록 기반 에디터**로 교체한다.

### 1.1 데이터 모델
- 문서 본문을 하나의 문자열이 아니라 **블록의 트리**로 다룬다. 각 블록은 최소
  `{ id, type, content, children[] }` 형태를 가진다.
- 지원 블록 타입: 본문(paragraph), 제목1/2/3(heading), 글머리 기호 목록(bulleted),
  번호 매기기 목록(numbered), 토글 목록(toggle, 접기/펼치기), 인용(quote), 코드
  블록(code), 구분선(divider), 체크박스(to-do).
- **계층구조**: `Tab`으로 들여쓰기(하위 블록화), `Shift+Tab`으로 내어쓰기. 토글 블록은
  하위 블록을 접었다 펼 수 있어야 한다(옵시디언 폴딩과 별개로, 노션 토글 자체 기능).
- mock 상태(React state)로만 관리하고 저장은 로컬(초안 저장 버튼 → 로컬 state 반영)에
  그친다. 서버 저장 API 연동은 하지 않는다.

### 1.2 마크다운 자동 변환 (노션과 동일 트리거)
새 블록의 맨 앞에서 아래를 입력하고 스페이스를 누르면 해당 블록 타입으로 즉시
전환되어야 한다(입력한 트리거 문자는 사라짐):

| 입력 | 결과 |
| --- | --- |
| `#` + space | 제목 1 |
| `##` + space | 제목 2 |
| `###` + space | 제목 3 |
| `-` 또는 `*` + space | 글머리 기호 목록 |
| `1.` + space | 번호 매기기 목록 |
| `>` + space | 인용 |
| `[]` 또는 `[ ]` + space | 체크박스(할 일) |
| ` ``` ` + Enter | 코드 블록 |
| `---` + Enter | 구분선 |

추가로 **`/`(슬래시) 명령 메뉴**를 지원한다 — 블록 맨 앞에서 `/`를 입력하면 위 블록
타입 목록이 뜨고 방향키+Enter로 선택 삽입할 수 있어야 한다. 이건 마크업 기억 없이도
블록을 넣을 수 있게 하는 노션의 핵심 진입점이라 빠지면 안 된다.

### 1.3 이 작업이 건드리는 화면
- `#/write` (문서 작성/편집) — 에디터 본체 교체.
- `#/link-documents` (관련 문서 연결) — 블록 에디터 안에서 `@` 또는 슬래시 명령으로
  문서를 인용/링크하는 진입점이 이상적이나, 이번 단계에서는 **기존 별도 화면 흐름을
  유지**하고 에디터 쪽엔 "관련 문서 연결" 진입 버튼만 자연스럽게 배치한다(화면 통폐합은
  범위 밖).
- `#/translation` (번역 보기) — 원문이 블록 구조로 바뀌므로, 번역본도 같은 블록 구조를
  유지해 원문↔번역 블록 단위 대조가 가능하도록 한다(1차가 만든 "AI 번역" 라벨/전환
  기능은 그대로 유지, 블록 구조 위에서 동작하게만 바꾼다).

## 2. AI 작성 보조 — 우측 하단 플로팅 패널

현재 AI 구조 추천이 `#/ai-structure`라는 **별도 페이지**로 빠져 있다. 이걸 문서 작성
화면(`#/write`) 안에서 뜨는 **우측 하단 플로팅 패널**로 바꾼다.

### 2.1 형태와 위치
- 화면 우측 하단에 고정되는 플로팅 패널(노션 AI 진입 버튼과 유사한 위치감). 기본은
  접힌 상태(아이콘/CIO 배지 버블)이고, 클릭하면 패널이 펼쳐진다.
- 문서 캔버스를 가리지 않는 오버레이 형태 — 모달이 아니다. 열려 있는 동안에도 본문
  편집이 계속 가능해야 한다.

### 2.2 "챗봇은 아니다" — 정확한 의미
Notion AI처럼 뜨되 Notion AI처럼 100% 대화형은 아니다. 즉:
- 패널의 기본 콘텐츠는 **채팅 로그가 아니라 제안 카드 피드**다. 각 카드는 기능명세서
  5.1이 정의한 것들을 그대로 담는다 — 구조 개선 제안, 누락된 섹션, 다음 문단 제안.
  카드마다 **수락 / 거부** 버튼이 있고, 수락해야만 본문(블록)에 반영된다(자동 반영 금지 —
  기능명세서 5.1 비즈니스 규칙 그대로 유지).
- 관련 문서 맥락 인용(`GET /writing-assistant/context`, Document Graph 기반)도 이 패널
  안에 별도 섹션으로 노출해, "이 문서와 연결된 다른 문서에서 참고한 내용"을 보여준다.
- 자유 질문을 위한 입력창은 **패널 하단에 보조적으로만** 둔다(대화가 주 기능이 아니라
  제안 피드가 주 기능이라는 우선순위를 지킨다).
- 표시는 항상 `CioBadge`(1차에서 만든 단일 CIO 정체성 컴포넌트)로 시작해, 다른 AI
  기능과 동일한 주체가 말하고 있음을 드러낸다.

### 2.3 `#/ai-structure` 라우트 처리
독립 페이지로 남겨두는 것 자체가 "AI 기능이 문서 작성의 흐름 밖으로 튕겨나가는" 문제의
원인이었다. 이 라우트는 **문서 작성 화면 안의 패널로 흡수**한다 — 즉 `#/ai-structure`로
직접 들어와도 결국 `#/write`의 해당 문서를 열고 패널이 펼쳐진 상태로 보여주는 형태로
정리한다(딥링크는 유지하되 별도 풀페이지 레이아웃은 없앤다). `화면-목록.md`에 이 변경을
반드시 기록한다.

## 3. Document Graph — 옵시디언식 거미줄(force-directed) 그래프

현재 `#/graph`(`DocumentGraphPage`)는 관계를 카드/목록에 가깝게 보여준다. 이걸
**옵시디언 그래프 뷰와 같은 노드-엣지 네트워크 그래프**로 바꾼다.

### 3.1 구조
- 캔버스 위에 문서를 점(노드)으로, 문서 간 관계를 선(엣지)으로 그리는 **force-directed
  레이아웃**(예: `d3-force` 등 가벼운 물리 시뮬레이션 라이브러리 사용). 노드는 서로
  밀어내고 엣지로 연결된 노드는 서로 당기는 방식으로 자동 배치되어야 한다.
- **인터랙션**: 드래그로 노드 이동, 휠/핀치로 확대·축소, 캔버스 팬(이동), 노드 클릭 시
  해당 문서 상세로 이동, 노드 hover 시 문서 제목/상태 툴팁.
- **시각적 구분**: 노드 크기(연결 수가 많을수록 크게) · 색(문서 상태 — `StatusBadge`와
  같은 색 규칙 재사용) · 현재 보고 있는 문서는 중심에 하이라이트.
- 비공개 문서(RACI 열람 권한 없음)는 흐리게/잠금 아이콘으로 표시하고 클릭 시 1차에서
  이미 정리한 권한 안내를 그대로 띄운다.

### 3.2 Document Graph의 역할은 그대로 유지
1차 결과서와 기능명세서가 규정한 대로 Document Graph는 DocumentLion·AI Writing
Assistant가 참조하는 **기반 인프라**다. 그래프 뷰를 시각적으로 바꾸더라도, 노드/엣지
데이터는 `src/data`에 단일 출처로 두고 다른 화면(AI 리뷰 근거, AI 작성 보조 패널의
"연결 문서 인용" 섹션 등)이 같은 데이터를 참조하도록 유지한다 — 그래프 화면 따로,
다른 화면의 "관련 문서" 목록 따로 만들지 않는다.

## 4. 전체 UX 재정비 — "기능 나열"에서 "노션 같은 화면"으로

1차 결과물에 대한 평가: **기능은 다 들어갔지만 화면마다 카드가 층층이 쌓여 있어
가독성이 떨어진다.** 이번엔 화면 단위로 정보 위계를 다시 잡는다.

### 4.1 원칙
- **화면당 주인공은 하나**: 지금처럼 대시보드·상세 화면에 동급 크기 카드를 5~8개씩
  나열하지 않는다. 가장 중요한 정보(예: Doc PR 상세라면 "지금 상태와 다음 행동")를
  화면 상단에 크게, 나머지는 아래로 내리거나 접는다.
- **점진적 노출(progressive disclosure)**: 이력·상세 근거·부가 메타데이터는 기본
  접힘(아코디언/토글) 상태로 두고 필요할 때 펼친다. 모든 정보를 항상 펼쳐서 보여주지
  않는다.
- **카드 남용 자제**: 모든 정보 단위를 테두리 있는 박스로 감싸지 않는다. 관련 정보는
  같은 섹션 안에서 여백과 타이포 위계(제목 크기/색)로 구분하고, 카드는 정말 독립된
  단위(예: 개별 리뷰 코멘트, 개별 Doc PR)에만 쓴다.
- **속성은 속성답게**: 노션 페이지 속성처럼, 상태·담당자·수정일 같은 메타데이터는 큰
  카드가 아니라 제목 아래 한 줄짜리 얇은 속성 목록으로 축소한다(1차가 이미 문서
  작성/상세 일부에 적용한 방향 — 이번엔 대시보드·목록형 화면까지 확대 적용).
- **동시에 보이는 액션 수를 줄인다**: 버튼/배지/안내 문구가 한 화면에 과도하게 나열된
  곳(대시보드, RACI 역할 관리, 승인권자 지정)은 1차 스크린샷 기준으로 재검토해 주(主)
  액션과 부(副) 액션을 시각적으로 분리한다.

### 4.2 우선 재정비 대상 화면
1차 결과서 4장·5장 기준으로 카드 밀도가 특히 높았던 화면부터 처리한다:
- 대시보드 — 통계 카드 4개 + Merge 차단 사유 + 최근 활동이 동시에 큰 카드로 나열됨 →
  통계는 얇은 요약 줄로, 차단 사유·활동은 접히는 리스트로.
- Doc PR 상세 — 요약 카드 1장 + 2단 카드 6장 구조 → 핵심 상태/액션을 상단에 압축하고
  나머지는 탭 또는 접기로.
- RACI 역할 관리 — 안내 카드 + 매트릭스 + 통계가 동시에 나열됨 → 매트릭스를 주인공으로,
  안내·통계는 보조 위치로.
- 팀 설정/관리 — 설정 카드들을 노션 설정 페이지처럼 좌측 메뉴 + 우측 단일 패널 구조로
  재편하는 것도 검토(현재는 카드 그리드).

## 5. 작업 순서 제안

1. **블록 에디터 도입** (`#/write`) — 나머지 세 작업의 전제가 되는 편집기 자체.
2. **AI 보조 패널** — 에디터가 준비된 뒤, 그 위에 얹는 패널. `#/ai-structure` 라우트
   흡수.
3. **Document Graph 캔버스 교체** — 독립적인 작업이라 2번과 병행 가능.
4. **전체 UX 재정비 패스** — 위 셋을 포함해 20개 화면 전체를 카드 밀도 기준으로 훑는다.
   1차가 만든 `Page`/`Section`/`Card`/`EmptyState`/`DataTable`을 그대로 쓰되, "얼마나
   쓸지"를 이번에 다시 판단한다.

각 단계가 끝나면 `normalization_v1.md`와 같은 형식으로 **2차 작업 기록 문서**를 남기고,
`화면-목록.md`의 라우트 변경사항(`#/ai-structure` 흡수 등)을 갱신한다.

## 6. 완료 기준 (Definition of Done)

- [ ] `#/write`에서 `#`, `-`, `>`, `1.`, `[]`, ` ``` `, `---` 입력 시 노션과 동일하게
      즉시 블록 타입이 전환된다.
- [ ] `/` 슬래시 명령으로 블록 타입을 선택해 삽입할 수 있다.
