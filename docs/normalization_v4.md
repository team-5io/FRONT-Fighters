## 1. 진단이 맞았다

3차가 카드를 64 → 44장으로 줄였는데도 "여전히 난잡하다"는 피드백이 나온 이유는
**우리가 `Card` 컴포넌트만 셌기 때문**이다. 사용자는 Card를 세지 않는다 — 눈에 보이는
선을 센다.

지시서 1장의 넓힌 정의(테두리 3면 이상 / 둥근 모서리 + 불투명 배경 / 그림자)로
다시 재니 숫자가 완전히 달랐다.

| 화면 | 3차 `Card` 계측 | 4차 컨테이너 계측 |
| --- | --- | --- |
| `documents` | **2** | **53** |
| `doc-pr` | **2** | **47** |
| `ai-structure` | 2 | 36 |

`documents`는 Card가 2장인데 화면에는 테두리·배경을 가진 요소가 53개 있었다.
표의 바깥 상자 + 헤더 배경 띠 + 행마다 반복되는 알약 배지 7개 + RACI 칩 7개 +
필터 상자 4개가 전부 "선"이었다.

## 2. 요소별 규칙 적용 (지시서 2장)

**컴포넌트를 고치면 여러 화면에 한 번에 반영된다**는 점을 살려, 화면이 아니라
공용 컴포넌트부터 손댔다.

| 요소 | 이전 | 이후 |
| --- | --- | --- |
| `Button` secondary | outline(테두리) | **테두리 제거**, hover에서만 옅은 배경. 테두리가 꼭 필요하면 새 `outline` variant를 명시적으로 |
| `StatusBadge` | 항상 알약 채움 | **`variant="inline"`(기본) = 점 + 텍스트** / `solid` = 알약. 상세 헤더 속성 줄에만 solid |
| `RaciChip` | 항상 알약 채움 | 같은 규칙 — 기본은 색 원 + 이름, 테두리·배경 없음 |
| `DataTable` | 바깥 상자 + 헤더 배경 띠 | **헤더 밑줄 1개 + 행 사이 가로선만.** 좌우 패딩도 첫/마지막 열은 0으로 |
| `ListFilterBar` | 상자 안에 인풋·필터 나열 | 검색은 밑줄 인풋, 필터는 테두리 없는 텍스트 버튼 |
| 폼 입력 (10개 파일) | 사방 테두리 박스 | **밑줄만.** 포커스에서 밑줄이 브랜드색으로. 여러 줄 입력은 영역이 보여야 해서 옅은 배경만 |
| 탭/세그먼티드 | 각 탭이 박스 | **밑줄 인디케이터** (선택 탭 아래 2px 브랜드색) |
| `Disclosure` | 이미 텍스트 + 화살표 | 유지 |
| 사이드바 선택 | 3차에서 `neutral-75`로 낮춤 | 유지 |

## 4. 신규 — 마이페이지 `#/me`

20개 화면 어디에도 개인 계정 화면이 없었는데 API 명세서에는 `PATCH /users/me`가
이미 "완료"로 있었다. **화면만 빠져 있던 상태**였다.

- **기본 정보** — 이름 / 이메일(읽기 전용) / 시간대 / 선호 언어
- **소속 팀** — 팀과 그 팀에서의 RACI 역할 (`raci.js` 재사용)
- **로그아웃** — `POST /auth/logout` 대응. 실제 호출 없이 로그인 화면으로 이동

알림 수신 설정·비밀번호 변경처럼 근거가 없는 항목은 "후속 단계 범위"로도 적지 않고
**아예 두지 않았다**(지시서 3.1).

처음부터 2장 규칙으로 만들어서 재정리가 필요 없다 — 컨테이너 5개(전부 셸)이고
화면 자체 컨테이너는 0이다. 진입점은 상단바 우측 아바타 + 이름이다.

## 5. 신규 — 뒤로가기

`PageHeader`에 `backTo` prop을 추가했다. 값을 주지 않으면
[`src/data/nav.js`](../src/data/nav.js)의 계층표에서 현재 해시로 찾아 쓴다 —
**화면마다 따로 적지 않아도 매핑이 한 곳에서 유지된다.**

14개 경로 전부 실제 클릭까지 검증했다.

```
OK doc-pr-detail -> #/doc-pr        OK translation     -> #/write
OK ai-review     -> #/doc-pr-detail OK raci-roles      -> #/settings
OK human-review  -> #/doc-pr-detail OK charter         -> #/settings
OK assign-approver -> #/doc-pr-detail OK glossary      -> #/settings
OK write         -> #/documents     OK team-members    -> #/settings
OK ai-structure  -> #/documents     OK team-reset      -> #/team-invite
OK link-documents-> #/write         OK me              -> 닫기
```

`#/write`는 노션 페이지 레이아웃이라 `PageHeader`를 쓰지 않아 뒤로가기를 직접 뒀다.
최상위 화면(대시보드·문서·Doc PR·그래프·설정)은 사이드바가 이동 수단이라 없다.

## 7. 판단이 필요했던 지점

1. **`RaciChip`의 색 원과 상태 점은 남겼다.** 넓힌 정의로는 "둥근 모서리 + 불투명
   배경"이라 컨테이너로 잡히지만, DESIGN.md가 정의한 역할 표기 수단이라 없애면
   R/A/C/I를 구분할 방법이 사라진다. 대신 이 둘을 감싸던 **알약**은 전부 걷어냈다.

2. **여러 줄 입력(textarea)만 밑줄에 옅은 배경을 더했다.** 한 줄 입력은 밑줄만으로
   영역이 읽히지만, 4~5줄 입력은 밑줄 하나로는 어디까지 쓸 수 있는지 알 수 없다.
   2장의 "구조적 테두리" 정의(경계를 알 수 없으면 남긴다)에 해당한다고 봤다.

3. **`ai-review`(22)는 상대적으로 덜 줄었다.** 검토 항목 3장이 Card인데, 3차에서
   "개별 검토 근거는 독립 단위"로 판단해 남긴 것이라 이번에도 유지했다.
