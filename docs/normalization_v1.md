## 1. 무엇을 왜 했나

1차 구현은 **Figma 좌표를 픽셀 단위로 재현하는 데만 집중**했다. 그 결과 디자인 원본에
들어 있던 결함이 그대로 화면에 남았다 — 빈 상태 미처리, AI 판단과 사람 판단의 시각적
미분리, 라벨 복붙 오류, 화면마다 다른 상태값 체계, 디자인 시스템과 반대로 매핑된 RACI 색.

이번 작업은 그 20개 화면을 **기획(기능명세서·유저플로우) 기준으로 다시 세운 것**이다.
가장 큰 변화는 화면 코드의 성격이 바뀐 것이다.

| | 1차 구현 | 정상화 이후 |
| --- | --- | --- |
| 기준 | Figma 좌표 | 기능명세서 · 유저플로우 · API 명세서 |
| 배치 | 절대 좌표 (`left-[393px] top-[298px]`) | 4/8/12/16/24 여백 리듬 |
| 상태값 | 화면마다 다른 문구 | `src/data/status.js` 한 곳 |
| 색 | 화면 파일에 hex/클래스 복사 | `src/data` + 공용 컴포넌트 |
| 화면 파일이 가진 것 | 좌표 + 색 + 문구 + 배치 | **그 화면에만 있는 내용과 배치** |

**범위 밖(지시서 0장 준수)**: API 연동 코드를 쓰지 않았다. mock 데이터는 그대로 두되
필드명·상태값만 API 명세서에 맞췄다. 기능명세서에 없는 기능은 만들지 않고 "후속 단계
범위"로 화면에 명시했다.

## 2. 만든 것 — 단일 출처

화면이 읽기만 하는 데이터 정의를 먼저 만들고, 그 위에 공용 컴포넌트를 얹었다.

| 파일 | 내용 | 근거 |

| `status.js` | Doc PR 상태 7종 (생성/AI리뷰/사람리뷰/반려/재제출/확정/리뷰어지정필요) | `GET /doc-prs/{prId}` |
| | 문서 상태 3종 (초안/리뷰중/공식) | 기능명세서 |

### 토큰 (`tailwind.config.js`)

- `neutral-75` (`#EDEDED`) — 램프에 비어 있던 단계. 회색 칩이 카드 배경에 묻히거나
  `neutral-100`으로 스냅되어 원본보다 진해지던 문제를 해결.
- `line` (`rgba(0,0,0,0.1)`) — 노션 톤의 1px 옅은 경계선. 카드·표·구분선의 기본값.
- **브랜드 컬러는 손대지 않았다** (`main-500 #9000FF` 유지).

## 4. 화면별 주요 변경

### 셸 (전 화면 영향)

- **사이드바**: 노션 워크스페이스 구조로 재편 — 팀 표시 → 섹션 트리 → 하단 설정(하위 5개).
  전부 `href="#"` 자리표시이던 링크에 **실제 라우트를 연결**했다.
- **상단바**: 80px → 52px. 검색만 남기고 아이콘 3개 제거.
- **라우트**: `#/ai-review`의 사이드바 선택을 `설정` → `Doc PR`로 정정
  (유저플로우 n23 → n51). `#/team-reset`은 설정에서 들어가므로 셸을 띄우도록 변경.
  인증/온보딩 3개는 셸 없이 렌더.

### 대시보드

사람/시스템 지표(3개)와 CIO 판단(1개)을 **다른 구획으로 분리**했다. Merge 차단 사유는
주체별 칩을 달고 `merge-check` 응답 항목과 1:1로 맞췄다.

### 목록형 (문서 / Doc PR)

노션 데이터베이스 표 뷰 톤 — 고정 헤더, hover 강조, 필터 바를 표 위에. Doc PR 목록에는
Doc PR마다 배정된 **내 역할 열**을 추가했다(역할 필터만 있고 정작 내 역할이 없던 문제).

### 리뷰/승인

**Doc PR 상세가 AI/사람 분리의 기준선**이다. CIO 카드는 info 띠 + 배지 + 안내,
사람 리뷰 카드는 main 띠 + 리뷰어 RACI 칩. 승인 버튼은 A 역할이 아니거나 차단 조건이
남아 있으면 비활성.

### 작성/번역

노션 페이지 톤의 핵심 적용 지점 — 넓은 단일 컬럼, 인라인 편집 제목, 제목 아래 속성 줄.
AI 제안은 본문과 구별되는 우측 패널에 두고 **수락해야만 반영**된다(기능명세서 5.1).

### 설정

Charter에 채택 동작을 넣어 `미채택`을 벗어날 길을 만들었고, 팀 관리자가 아니면 입력을
잠근다. 승인권자 지정과 팀원 관리는 **단위를 나눠** 정리했다 — 전자는 Doc PR 하나,
후자는 팀 단위. 서로 링크를 걸었다.

## 6. 판단이 필요했던 지점 (확인 요청)

1. **`NOTION_DESIGN.md`가 리포에 없다.** 지시서 3장이 참조하지만 파일이 없어, 3장 본문이
   직접 명시한 톤 기준(4/8/12/16/24 여백, 12px 라운드 + 1px 옅은 보더, 그림자 없음)과
   "일반적으로 알려진 노션 앱 구조 관용구"로 진행했다. 실측 데이터가 있다면 대조가 필요하다.

2. **승인권자 지정 ↔ 팀원 관리를 합치지 않았다.** 지시서 5.K가 "중복이면 한쪽으로 흡수"를
   열어 뒀지만, API가 `PATCH /doc-prs/{prId}/approver`(Doc PR 단위)와 팀 단위 목록으로
   나뉘어 있어 단위를 구분하는 쪽을 택했다. 합치는 편이 맞다면 되돌릴 수 있다.

3. **Figma 좌표 메모를 지우지 않았다.** `화면-목록.md`의 화면별 실측 기록은 "1차 구현
   이력"으로 접어 두었다. 원본 디자인의 어느 부분이 어긋나 있었는지가 디자이너와의 대화에
   쓰일 수 있다고 봤다.

4. **`CURRENT_USER`는 A 역할·팀 관리자로 고정된 mock이다.** 권한 분기 자체는 구현했지만
   (`canManageTeam()`, 역할별 잠금), 다른 역할로 들어왔을 때의 화면은 이 값을 바꿔야
   확인할 수 있다. 로그인 연동 시 이 자리를 실제 세션으로 교체하면 된다.

## 7. 다음 단계 제안

  별도 파일로 분리해도 좋다.
