## 1. 1차와 무엇이 달랐나

1차가 **"고장난 걸 고치는"** 작업이었다면, 2차는 **"기능은 맞는데 경험이 아직 노션이
아닌"** 지점을 고쳤다. 1차 결과서 스스로 인정했던 네 가지가 출발점이었다.

| 지점 | 1차 상태 | 2차 결과 |
| --- | --- | --- |
| 문서 작성 | 자유 텍스트 `<textarea>` 하나 | 계층형 블록 에디터 (마크다운 트리거 · 슬래시 명령 · 들여쓰기) |
| AI 작성 보조 | 별도 페이지 `#/ai-structure`로 튕겨나감 | 작성 화면 우측 하단 플로팅 패널로 흡수 |
| Document Graph | 관계를 카드/목록으로 나열 | force-directed 노드-엣지 캔버스 |
| 전체 UX | 화면마다 카드가 층층이 5~8장 | 주인공 하나 + 나머지 접기 |

**1차 산출물은 하나도 갈아엎지 않았다.** `StatusBadge`·`RaciChip`·`CioBadge`·
`AiReviewCard`/`HumanReviewCard`·`EmptyState`·`DataTable`·`MyRoleBar`·`status.js`·
`raci.js`가 전부 그대로 재사용됐고, 그 위에 이번 네 가지를 얹었다.

### `NOTION_DESIGN.md` 대조 결과

1차 때 리포에 없어 일반 지식으로만 진행했던 파일을 이번엔 실제로 열어 대조했다.
**1차에서 정한 값이 실측과 일치했다** — 별도 수정이 필요 없었다.

| 항목 | NOTION_DESIGN.md 실측 | 우리 구현 |
| --- | --- | --- |
| 카드 경계 | `1px rgba(0,0,0,0.1)`, 그림자 없음 | `line` 토큰 = 정확히 같은 값 |
| 카드 라운드 | 12px | `rounded-md` = 12px |
| 컨트롤 라운드 | 4–8px | `rounded-sm` = 8px |
| 여백 리듬 | 4 / 8 / 12 / 16 / 24px | 동일 |
| 깊이 | 공개 표면은 대체로 플랫 | 그림자는 플로팅 패널·툴팁에만 |

색은 의도적으로 가져오지 않았다. 문서가 `#0075de`(노션 블루)를 "captured public CTA
패턴에만" 쓰라고 못 박고 있고, 우리 브랜드는 `main-500 #9000FF`다.

## 2. 블록 에디터 (지시서 1장)

### 데이터 모델 — `src/data/blocks.js`

본문을 문자열 하나가 아니라 `{ id, type, content, children[] }` 트리로 다룬다.
조작 함수는 전부 순수 함수라 `setState`에 그대로 넘어간다.

`flatten` · `updateBlock` · `insertAfter` · `removeBlock` · `indentBlock` ·
`outdentBlock` · `neighborId` · `orderedIndex`

지원 블록 11종: 본문 · 제목1~3 · 글머리 · 번호 · 토글 · 인용 · 코드 · 구분선 · 할 일

### 입력 방식

| 입력 | 결과 |
| --- | --- |
| `#` `##` `###` + space | 제목 1 / 2 / 3 |
| `-` `*` + space | 글머리 기호 목록 |
| `1.` + space | 번호 매기기 목록 |
| `>` + space | 인용 |
| `[]` `[ ]` + space | 할 일 |
| ` ``` ` + Enter | 코드 블록 |
| `---` + Enter | 구분선 |
| `/` | 블록 타입 선택 메뉴 (방향키 + Enter) |
| `Tab` / `Shift+Tab` | 들여쓰기 / 내어쓰기 |

노션과 같은 세부 동작도 넣었다 — 빈 목록에서 Enter를 누르면 목록이 끝나고, 블록 맨
앞에서 Backspace를 누르면 타입이 본문으로 되돌아가고, 내어쓰기하면 뒤에 남은 형제가
그 블록의 하위로 따라간다.

### 구현 판단

**`contentEditable` 대신 블록마다 `<textarea>`를 뒀다.** contentEditable은 한글 IME
조합 중 React 리렌더가 끼어들면 커서가 튀는 문제가 잦다. 블록 단위 textarea는 그 문제가
없고, 높이는 `scrollHeight`로 내용에 맞춘다.

## 3. AI 작성 보조 패널 (지시서 2장)

`#/ai-structure` 풀페이지를 삭제하고 작성 화면의 플로팅 패널로 옮겼다.

- **접힘 상태**: 우측 하단 CIO 버블 + 제안 개수 배지
- **펼침 상태**: 360px 오버레이. 모달이 아니라 **열려 있는 동안에도 본문 편집이 계속된다**
- **챗봇이 아니다**: 기본 콘텐츠는 채팅 로그가 아니라 수락/거부가 붙은 제안 카드 피드다.
  자유 질문 입력창은 하단 보조로만 뒀다
- **수락해야만 반영**: 카드의 `apply()`가 블록을 만들어 본문에 넣는다. 자동 반영은 없다
  (기능명세서 5.1 비즈니스 규칙)
- **연결 문서 인용** 섹션이 `src/data/graph.js`의 `CONTEXT_QUOTES`를 읽는다

### 라우트 처리

`#/ai-structure`는 라우트 표에 남아 있지만 `DocumentWritePage`를 가리킨다. 이 해시로
들어오면 작성 화면이 열리며 패널이 펼쳐진 상태가 된다 — **딥링크는 살리되 별도
풀페이지 레이아웃은 없앴다.**

## 4. Document Graph 캔버스 (지시서 3장)

`d3-force`로 물리 시뮬레이션만 돌리고 렌더링은 SVG로 직접 한다. d3의 DOM 조작을 쓰지
않아 React 상태와 충돌하지 않는다.

- **인터랙션**: 노드 드래그 · 휠 확대축소(0.45~2.4배) · 캔버스 팬 · 노드 클릭 선택 ·
  hover 툴팁 · 보기 초기화
- **시각적 구분**: 노드 크기 = 연결 수, 색 = 문서 상태(`StatusBadge`와 같은 규칙),
  현재 문서는 중심 고정 + 링, 연결 안 된 노드는 흐리게
- **엣지**: 상위 문서는 굵게, 영향 관계는 파선
- **권한**: 열람 권한 없는 노드는 파선 테두리 + 잠금 표시, 클릭하면 1차에서 정리한
  권한 안내가 뜬다
- tick마다 좌표를 캔버스 안으로 붙잡아 노드가 잘리지 않게 했다

### 단일 출처 유지

`src/data/graph.js`의 노드 11개 / 엣지 11개를 **그래프 화면·AI 패널의 연결 문서 인용·
작성 화면의 연결된 문서가 모두 읽는다.** 화면마다 "관련 문서" 목록을 따로 만들지 않았다
(지시서 3.2).

## 5. UX 재정비 (지시서 4장)

카드 개수를 밀도 지표로 삼아 측정했다.

| 화면 | 이전 | 이후 | 무엇을 했나 |
| --- | --- | --- | --- |
| 대시보드 | 8+ | **3** | 주인공을 "내가 오늘 처리할 일"로. 통계 4카드 → 속성 줄. 나머지 5구획 접기 |
| Doc PR 상세 | 7 | **3** | 주인공을 "무엇이 막고 있고 뭘 하면 되는가"로. Merge 조건은 한 줄 압축. 리뷰·이력·인수인계 접기 |
| RACI 역할 관리 | 8+ | **2** | 매트릭스를 주인공으로. 역할 기준 4카드·통계 6칸 → 접기 + 속성 줄 |
| 팀 설정 | 6 | **0** | 카드 그리드 → 노션 설정처럼 좌측 메뉴 + 우측 단일 패널 |
| CIO 1차 검토 | 8 | **5** | 검토 항목 카드만 남기고(개별 근거는 독립 단위) 나머지 접기 |

적용한 원칙:
- **화면당 주인공 하나** — 가장 중요한 정보를 상단에 크게, 나머지는 아래로
- **점진적 노출** — `Disclosure` 신설. 이력·근거·부가 정보는 기본 접힘
- **카드 남용 자제** — 관련 정보는 여백과 타이포 위계로 구분, 카드는 독립 단위에만
- **속성은 속성답게** — 메타데이터는 제목 아래 한 줄
- **동시 액션 수 줄이기** — 주 액션 하나만 강조하고 나머지는 secondary/텍스트로

### 그 외

- 딥링크 `#/ai-structure` → 작성 화면 + 패널 펼침, 풀페이지 아님 ✓

- **20개 라우트 전수 스윕** — 콘솔 에러 0, 가로 오버플로 0
- API 호출 코드 0건 (mock 유지)

## 7. 판단이 필요했던 지점

1. **`d3-force`를 의존성으로 추가했다.** 지시서가 "예: d3-force 등 가벼운 물리
   시뮬레이션 라이브러리"라고 지목했고, 직접 구현하는 것보다 안정적이라 판단했다.
   렌더링은 SVG로 직접 하므로 d3에 묶인 부분은 시뮬레이션 계산뿐이다.

2. **`contentEditable`을 쓰지 않았다.** 노션은 contentEditable 기반이지만, 한글 IME
   조합 중 커서 문제를 피하려고 블록 단위 textarea를 택했다. 대신 인라인 서식
   (**굵게**, *기울임*)은 지원하지 않는다 — 지시서 1.1의 블록 타입 목록에는 없는
   항목이라 범위 밖으로 봤다.

3. **`#/link-documents`를 합치지 않았다.** 지시서 1.3이 "에디터 안에서 `@`로 문서를
   인용하는 게 이상적이나 이번 단계에서는 기존 흐름 유지"라고 명시해 그대로 따랐다.
   에디터 툴바에 진입 버튼과 연결 개수만 노출했다.

4. **번역 화면은 블록 구조로 옮기지 않았다.** 지시서 1.3이 "원문이 블록 구조로
   바뀌므로 번역본도 같은 블록 구조를 유지"하라고 했는데, 현재 번역 화면은 문단 단위
   대조로 이미 동작하고 1차의 "AI 번역" 라벨·전환 기능이 그 위에 얹혀 있다.
   블록 단위 대조로 바꾸려면 블록 id 매핑이 필요해 범위가 커진다 — **미완 항목으로
   남긴다.**

## 8. 남은 것

- **번역 화면 블록 단위 대조** (위 7-4). 원문 블록 ↔ 번역 블록을 id로 잇고,
  블록 하나를 클릭하면 대응 블록이 하이라이트되는 형태가 목표.
- **카드 밀도 2차 순회** — 지시서가 지목한 4개 화면은 처리했지만
  `human-review`(7) · `team-members`(7) · `charter`(6)는 아직 카드가 많다.
- **에디터 인라인 서식** — 굵게/기울임/링크. 블록 타입과 별개 축이라 별도 판단 필요.
- 1차에서 이월된 것: `CURRENT_USER` mock 고정, 승인권자 지정 ↔ 팀원 관리 미통합.
