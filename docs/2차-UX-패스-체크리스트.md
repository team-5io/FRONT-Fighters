# 2차 UX 패스 체크리스트

1차(Figma 그대로 구현) 중 발견했지만 의도적으로 손대지 않은 항목. 전체 화면 구현이
끝난 뒤 `CLAUDE.md`의 "UX 리팩터링 원칙" 기준으로 순회하며 처리한다.

## AI/사람 리뷰 분리 (원칙 3)

> "AI 결과는 별도 탭 또는 섹션으로 구분하고, 옆에는 항상 '참고용, 최종 결정은 A 역할' 안내를 붙인다"

### 대시보드 — 통계 카드 (Figma 17:140)

`전체 Doc PR` · `검토 대기` · `AI 반려` · `승인 완료 · Merge 대기` 4개가 같은 크기,
같은 형태, 같은 줄에 놓여 있다. **`AI 반려`만 AI 판단이고 나머지 셋은 사람/시스템
상태**인데 시각적으로 구분이 없어, AI 판정이 승인 완료와 동급의 확정 상태로 읽힌다.

- 검토 방향: AI 계열 지표를 별도 그룹으로 묶거나, AI 카드에 "AI 1차 검토" 라벨을 붙인다.

### 대시보드 — Merge 차단 사유 (Figma 17:140)

한 목록에 AI 판단과 사람/시스템 사유가 섞여 있다.

| 칩 | 판단 주체 |
| --- | --- |
| AI 반려 — 규칙 위반 : 검토 기준 미충족 | **AI** |
| 사람 리뷰 미완료 — 리뷰어 응답 대기중 | 사람 |
| 승인 권자 부재 — A 역할 승인 권자 미지정 | 조직/권한 |
| 충돌 미해결 — 문서 버전 충돌 감지됨 | 시스템 |

- 검토 방향: AI 사유를 분리하거나 칩 색으로 주체를 구분하고, AI 항목에는 "참고용,
  최종 결정은 A 역할" 안내를 붙인다.

### Doc PR 상세 — 분리는 됐지만 안내가 없다 (Figma 38:775)

이 화면은 `AI 리뷰`와 `사람 리뷰`를 **별도 카드로 분리**해 원칙 3을 절반은 지킨다.
다만 AI 리뷰 카드 어디에도 **"참고용, 최종 결정은 A 역할"** 안내가 없다.
`Merge 조건 체크`에서도 `AI 리뷰 완료`(AI)와 `사람 리뷰 전원 완료 필요`(사람)가
같은 배지·같은 톤으로 나열된다.

- 검토 방향: AI 리뷰 카드에 안내 문구를 붙이고, 다른 화면(대시보드·Doc PR 목록)도
  이 화면의 분리 방식을 기준으로 맞춘다.

### 대시보드 — 최근 Doc PR 활동 (Figma 17:140)

`AI 반려 · 규칙 위반 · 1시간 전`(AI)과 `승인 완료 · 이정민 · 8분 전`(사람)이
같은 메타 줄 형식으로 표시된다. 우측 상태 칩(`반려됨` / `검토 차단`)도 톤이 같다.

- 검토 방향: 주체를 드러내는 접두 라벨이나 아이콘을 붙인다.

## 그 밖에 기록해 둔 것

### 빈 상태 (원칙 4)

- **팀 초대 화면(Figma 4:86)의 `플랜` 값이 비어 있다.** 라벨만 있고 값 노드가 없어
  1차에서는 빈 칸으로 뒀다. 미정 슬롯인지 확인 후, 빈 상태 문구를 넣을지 정한다.

- **문서 목록 화면(Figma 17:212)의 본문 텍스트가 전부 스켈레톤 바다.** Figma에서
  `#D9D9D9` 회색 막대로만 그려져 있어 1차에서는 그대로 옮겼다
  (`neutral-100`, `DocumentsPage.jsx`의 `SkeletonBar`).
  - 목록 7행의 부제 (제목 아래 169×12 막대)
  - 상세 카드 `문서 요약`의 본문 2줄 (252×12, 163×12)
  - 상세 카드 `최근 변경`의 3줄 (252×12 ×3)
  - 상세 카드 `연결된 Doc PR`의 빈 박스 2개 (296×61)

  실제 문구가 정해지면 교체한다. 그때 **원칙 4(빈 상태는 시스템 목소리로 무엇이 왜
  비어있는지 + 다음 행동을 함께 안내)** 를 적용할 것 — 지금은 로딩인지 데이터 없음인지
  구분되지 않는다. 특히 `연결된 Doc PR`은 "연결된 Doc PR이 없습니다 — Doc PR을
  만들어보세요" 같은 안내가 필요한 자리로 보인다.

- **협업 규칙 화면(Figma 26:1829)의 규칙 3장이 전부 빈 상태다.** 제목(`초안 공유 시점` /
  `응답 속도 기준` / `리뷰어 지정 원칙`)만 있고 본문 입력과 `Doc PR 연동기준` 셀렉트가
  모두 자리표시다. 화면 안내는 "AI가 팀 협업 패턴을 분석해 생성한 초안입니다"라고 하는데
  정작 초안 내용이 없어, **AI가 무엇을 제안했는지 읽을 수 없다.** 실제 문구가 정해지면
  채운다. 연동기준 셀렉트도 선택지가 `AI 리뷰 기준` 하나뿐이라 나머지 값을 확인해야 한다.

- **팀 용어집 화면(Figma 30:106)의 표가 통째로 빈 상태다.** 머리 행(`원문 (Source)` /
  `번역어` / `설명` / `등록자` / `등록일`)만 있고 5개 행이 전부 비어 있는데, **"아직 등록된
  용어가 없습니다" 같은 안내가 없어 로딩 중인지 데이터가 없는지 구분되지 않는다.**
  바로 아래 `용어 추가` 카드가 다음 행동에 해당하므로, 빈 상태 문구에서 그쪽으로
  유도하면 된다(원칙 4). 페이지네이션도 `1` 한 장만 활성인 채 `<` `>`가 함께 떠 있다 —
  결과가 한 페이지뿐일 때의 표시를 정한다.
  - `카테고리` 셀렉트의 선택지도 `일반` 하나뿐이라 나머지 값을 확인해야 한다.
  - CLAUDE.md의 Dev-aware Translation 규칙(코드/기술 용어/고유명사 원문 보존)이
    이 용어집을 근거로 도는지 확인하고, 그렇다면 그 관계를 화면에 드러낼지 정한다.

### 협업 규칙 — 채택 동작이 화면에 없다 (Figma 26:1829)

배지가 `초안 - 미채택`이고 안내문이 "내용을 검토하고 수정한 뒤 **공식 채택하세요**"라고
지시하는데, 하단 버튼은 `취소` / `변경 사항 저장` 둘뿐이다. **채택으로 넘어가는 진입점이
어디에도 없어 `미채택` 상태에서 벗어날 방법이 화면상 없다.**

CLAUDE.md 도메인 규칙상 Charter는 DocumentLion의 리뷰 근거이고, 채택은 A 역할의 결정에
해당한다. 아래 셋을 함께 정해야 한다.

- 채택 버튼(또는 `변경 사항 저장`과의 관계 — 저장이 곧 채택인지, 별도 단계인지)
- 채택 권한을 가진 역할과, 그 외 역할이 이 화면에 들어왔을 때의 표시
- `규칙 수정 후 재채택하면 이후 생성되는 Doc PR부터 새 기준이 적용됩니다`가 안내로만 있고
  재채택 동작이 없다 — 안내와 실제 조작을 맞춘다

### 번역/다국어 표시 (원칙 5)

> "번역된 콘텐츠는 원문과 시각적으로 구분(라벨, 배경 등)하고 원문 보기로 전환 가능해야 한다"
> CLAUDE.md 도메인 규칙: **번역본에는 반드시 "AI 번역" 라벨 표시**

- **번역 보기 화면(Figma 23:672)에 "AI 번역" 라벨이 없다.** 번역문 패널이 보라 틴트
  배경으로 원문과 구분되긴 하지만, 라벨은 어디에도 없다. Figma 원본에 없어 1차에서는
  넣지 않았다 — 필수 요구사항이므로 디자이너와 확인 후 추가한다.
- 원문 ↔ 번역문 전환(원문 보기) 동작이 없다. 현재는 좌우 병렬 비교만 가능하다.
- 문서 목록·Doc PR 목록 등 다른 화면에도 번역본 표기가 전혀 없다. 번역된 문서를
  목록에서 어떻게 표시할지 정해야 한다.

### RACI 색 규칙이 두 갈래다 — 먼저 정해야 할 것 (Figma 26:1697)

`RACI 역할 관리` 화면을 구현하면서 드러났다. **디자인 시스템과 Figma가 서로 다른 색을 쓴다.**

| 역할 | `CLAUDE.md` RaciChip | Figma 26:1697 | 1차 구현 |
| --- | --- | --- | --- |
| R (실행 담당) | info | `#9000FF` | `main-500` |
| A (승인 책임) | main | `#000DFF` | `info` (`#3B4CFF`, 원본보다 탁함) |
| C (검토 협력) | warning | `#00E626` | `success` (`#00C853`, 원본보다 탁함) |
| I (결과 통보) | neutral | `#FF9D00` | `warning` |

R과 A가 정확히 뒤바뀌어 있어, 두 규칙을 섞으면 **가장 강한 권한인 A(유일한 최종 결정권자)의
색이 화면마다 달라진다.** 1차에서는 Figma를 따랐다.

- 검토 방향: 한쪽으로 확정한 뒤 `src/components/ui/`에 `RaciChip`을 만들어 색 규칙을 한곳에 모은다.
  지금은 `RaciRolesPage.jsx`의 `ROLE_GUIDE` · `ROLE_COLS` · `MATRIX_COLS` · `STATS` 네 군데에
  같은 색 배열이 반복된다. `#000DFF` / `#00E626`을 토큰으로 승격할지도 함께 정한다.

### RACI 가시성 (원칙 2)

- 지금까지 구현한 화면(로그인 / 팀 초대 / 팀 설정 초기화 / 대시보드 / 문서 목록 /
  Doc PR 목록) 어디에도 **현재 사용자의 RACI 역할과 그로 인해 가능한 행동이 드러나지
  않는다.** 기능명세서 3장 권한 매트릭스와 대조해 역할별 노출/숨김을 정리한다.
  - 특히 팀 설정 초기화는 A 역할 전용 동작으로 보이는데 권한 안내가 없다.
  - Doc PR 목록에 `역할` 필터가 있지만 "내 역할이 무엇인지"는 화면에 없다.
  - **RACI 역할 관리(26:1697)는 팀원 전원의 역할을 바꾸는 화면인데 권한 표시가 없다.**
    `권한 안내` 패널은 "A가 지정되지 않은 문서" 안내일 뿐, 보고 있는 사람이 이 화면을
    쓸 수 있는지는 알려주지 않는다. 승인권자 지정(51:508)의 `지정 조건 안내`가
    "팀 관리자만 이 작업을 수행할 수 있습니다"라고 밝히는 것과 대비된다.
    C·I 역할로 들어오면 체크박스와 `변경 사항 저장`을 어떻게 처리할지 정해야 한다.

### 상태 배지 규칙 정리

Doc PR 목록(Figma 17:284)의 배지 7종이 규칙에서 벗어난 곳이 있다.

- **`반려`만 테두리 규칙이 다르다.** 나머지는 전부 `배경 = 연한 틴트` +
  `테두리 = 같은 색 반투명`인데(승인 대기 `#FFF4E5` + `rgba(255,157,0,0.43)`),
  `반려`만 테두리가 `#FFE1E0` 실색이라 배경 `#FFF3F2`와 거의 같은 색이 된다.
  1차에서는 다른 배지와 같은 규칙(`error/40`)으로 맞췄다.
- **같은 글자 수인데 폭이 다르다.** `승인 대기` 88px / `검토 대기` 76px.
  1차에서는 자동 폭이라 둘 다 87.4px — `검토 대기`가 Figma보다 11px 넓다.
- 배지 상태값이 화면마다 다른 체계다. 문서 목록은 `공식 / 초안 / 리뷰중`,
  Doc PR 목록은 `승인 대기 / AI 리뷰중 / 반려 / 재제출 / 확정 / 검토 대기 /
  리뷰어 지정 필요`. 기능명세서의 상태 정의(draft/review/merged/rejected)와 대조해
  정리하고, `Badge` 컴포넌트로 통일할 대상인지 판단한다.
  - 여기서 **원칙 3(AI/사람 리뷰 분리)** 과도 얽힌다. `AI 리뷰중`(AI)과
    `검토 대기`·`승인 대기`(사람)가 같은 모양·같은 자리에 놓여 구분되지 않는다.
